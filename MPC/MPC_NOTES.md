## 0. 무엇을 만들었나 — 한 문장

서 있기 컨트롤러의 힘 배분을 `np.linalg.lstsq` 한 줄에서 **시간지평 N=10짜리
제약 있는 wrench QP(convex MPC)** 로 교체했고, 그 결과 순수 피드포워드가
넘어졌던 40 N 외란을 **관절 PD 없이** 회복하게 됐다 (80 N까지 버팀).

```
[매 10ms]  MuJoCo 상태 → x(13) 추출 → QP 풀기 → 발별 wrench W_L, W_R (각 6)
[매 2ms]   τ = qfrc_bias − Σ J_iᵀ W_i  → 29개 관절 토크 인가
```

층1(재료: 상태방정식·제약·참조 조립)과 층2(솔버) 구분 그대로:

## 2. 모델 요약

상태 (13): `x = [roll, pitch, yaw, px, py, pz, wx, wy, wz, vx, vy, vz, g]`
— Θ는 ZYX 오일러, p·v는 **CoM**(pelvis 아님), ω는 world, g=9.81은 Di Carlo 트릭
(상수를 상태에 넣어 아핀 항을 선형으로 유지).

입력 (12): `u = [W_L, W_R]`, `W = [Fx, Fy, Fz, mx, my, mz]` — **발 site(발목 원점)에
작용하는 wrench, world frame**. quadruped(발4×힘3)와 차원이 12로 같지만 내용이 다름:
발 2개 × (힘3 + **발목 모멘트3**). 모멘트가 생기는 이유는 발이 면접촉이라서.

연속 동역학 → [src/mpc_srb.py](src/mpc_srb.py) `continuous_AB`:
```
Θ̇ = Rz(ψ)ᵀ ω                       ← Di Carlo 식 (12), 작은 roll/pitch 근사
ṗ = v
ω̇ = I_w⁻¹ Σᵢ (rᵢ×Fᵢ + mᵢ)          ← rᵢ = 발 site − CoM (CoM 기준!)
v̇ = (1/M) ΣᵢFᵢ − g ẑ
ġ = 0
```
B_c에서 quadruped 대비 새 블록은 **ω̇ 행의 모멘트 3열 = I_w⁻¹** 뿐.
이산화는 Euler: `A_d = I + A_c·dt`, `B_d = B_c·dt`, dt = 0.02 s.

파라미터 (전부 모델에서 추출, `make_params`):
- M = 33.341 kg, I_body diag ≈ [3.549, 3.175, 0.542] kg·m²
- 발: l_t = 0.12 (발가락), l_h = 0.05 (뒤꿈치), **w = 0.025** (좌우 반폭)
  - ⚠ 명세는 w=0.03이었지만 XML 실측은 뒤꿈치 y=±0.025 → 보수적으로 0.025 사용

## 3. 제약 (발당 10행, `foot_constraints`)

```
마찰 피라미드:  ±Fx ≤ μFz,  ±Fy ≤ μFz          (μ=0.6)
수직력:         10 ≤ Fz ≤ 500 N
롤 CoP:         |mx| ≤ w·Fz                       (G1은 ankle-roll 있어서 범위 제약.
                                                   MIT Humanoid는 mx=0 강제였음)
피치 CoP:       −l_t·Fz ≤ my ≤ l_h·Fz            (비대칭! 앞 0.12 / 뒤 0.05)
```
전부 `(계수)·Fz` 와의 1차 결합이라 **선형** → QP에 그대로 들어간다.
mz 제약은 초기 단계라 생략 (R 벌점만).

## 4. QP (condensed, Di Carlo 식 27–32)

```
X = A_qp x0 + B_qp U          A_qp = [A_d; A_d²; …],  B_qp 하삼각 블록
min ½UᵀHU + gᵀU               H = 2(B_qpᵀQ̄B_qp + R̄)
                              g = 2B_qpᵀQ̄(A_qp x0 − X_ref) − 2R̄·U_ref
s.t. C U ≤ d                  (3절 제약 × 2발 × N)
```
- N=10, dt=0.02 → **0.2 s preview**. MPC 재계산 100 Hz, 토크는 500 Hz로 재계산
  (wrench는 유지하되 J, qfrc_bias는 매 스텝 갱신).
- 솔버: **quadprog** (Goldfarb–Idnani active-set). 평균 6 ms/solve (N=10, 120변수,
  200제약, 밀집). N=1이면 0.4 ms.
- ⚠ CasADi의 qpOASES 등 conic 플러그인은 **한글 경로에서 DLL 로딩 실패**(WIN32 126)
  — CasADi는 자동미분(Step 3)에만 사용. MuJoCo 로딩(assets dict 우회)과 같은 계열 문제.

## 5. 검증 결과 (명세 10절 순서)

### Step 1 — 부호 규약 ✓
lstsq 서 있기 해로 my를 두 방식(외적 직접 / −Fz·x_CoP)으로 계산:
**둘 다 −2.116 N·m (왼발)** 로 일치, 범위 [−19.6, +8.2] 안.
- ⚠ 명세의 예상값 −3.87은 **world 원점 기준** 모멘트(−163.5×0.0237)였다.
  제약의 l_t/l_h는 **발목 기준**이므로 발목 기준 x_CoP = 0.0237−0.0108 = 0.0129,
  my = −2.11이 올바른 통과값. 부호(음수=CoP가 발목 앞)는 두 기준 동일.
  → 명세 11절이 경고한 '기준점 혼동'의 실제 사례.

### Step 2 — N=1 QP 서 있기 ✓
- 회귀: QP vs lstsq 발별 wrench — Fz 163.53 vs 163.65, my −1.77 vs −2.12 (근사 일치)
- 10초 서 있기: drift **+0.0002 m**, 실접촉력 합 [0.009, 0, 327.078] N, 위반 0
- N=1의 정체: Euler 1스텝에서 u는 속도(ω,v)에만 영향 → 위치·자세 피드백 **없음**.
  사실상 "wrench 균형 + 속도 댐핑". 위치 피드백은 N≥2부터 생긴다.

### Step 3 — 자동미분 대조 ✓
CasADi로 f(x,u)를 심볼릭으로 적고 jacobian(f,x), jacobian(f,u) 평가:
**max|A_sym−A_hand| = 0, max|B_sym−B_hand| = 2.2e-16** (기계 정밀도).

### Step 4 — N=10 MPC + 외란 ✓
- 초기해 N=10 vs N=1: Fz 동일, N=10이 my=−2.113(lstsq와 일치), Fx≈0으로 더 정확
  (지평이 길어지면 "Fx로 잠깐 때우기"가 미래 위치 오차로 벌점받기 때문)
- 20초 생존, drift +0.0007 m, 위반 0
- **40 N/0.1s 밀기 2회 회복** — pitch 최대 0.35°, CoM 오차 4 mm, my −2→−15 N·m
  스윙 후 복귀 ([logs/standing_mpc_n10_20260910_184000.png](logs/standing_mpc_n10_20260910_184000.png))
- 외란 여유: **80 N 버팀, 120 N 쓰러짐**. 120 N×0.1 s → Δv≈0.36 m/s는 발 길이
  17 cm의 ankle strategy(CoP 이동) 한계 밖 — 그 너머는 **스텝을 밟아야 하는 영역**
  = Step 5(gait)가 필요한 이유의 실물 증거.

## 6. 디버깅 기록 — 4번 터졌고, 전부 교훈이 됐다

이 절이 이 문서의 핵심이다. 명세대로 짰는데 안 됐던 것들.

### (1) u_ref=0이면 R이 중력과 싸운다 — Fz가 256 N밖에 안 나옴
첫 실행에서 QP가 Fz=127.96/발 (합 256 ≠ 327)을 뱉고 5.5 cm/s로 가라앉았다.
원인: 비용 `‖u‖²_R`은 u=0을 선호 → 중력 지탱에 필요한 힘과 타협한다.
해석적으로 F* = Mg·[2Q_v(dt/M)²] / [2Q_v(dt/M)² + R_F] = 0.783·Mg = 256 N — 출력과
정확히 일치. **해법: u_ref = 중력 피드포워드(발당 Mg/2)를 기준으로 정규화**
(`‖u−u_ref‖²_R`). 명세의 "u_ref=0으로 시작"은 R이 충분히 작을 때만 무해하다.

### (2) R_moment ≫ R_force 면 QP가 모멘트 대신 Fx로 피치를 만든다
R_m=1e-3 (힘의 100배)로 두자 QP가 my=−2.1 대신 my=−0.1 + **Fx=+2.7 N**을 선택
(모멘트가 비싸니 "싼" 수평력으로 피치 균형). 순수 전진력이 남아 로봇이 밀려가다
넘어짐. **해법: R_m = R_F = 1e-5.** 명세의 "힘/모멘트 가중 분리"는 방향이 반대였다
— 모멘트는 CoP 제약이 물리 한계를 지켜주므로 벌점은 가볍게 두는 게 맞다.

### (3) 자세 가중이 크면 이산 루프가 발산한다 — 대역폭 계산
Q_Θ=300, Q_ω=5로 두자 서자마자 50 Hz 업데이트 주기마다 my가 부호 교대하며
증폭(−2.19/−1.78/−2.26/…) → 0.38 s에 bang-bang 발산. LQR 근사로 추정하면 이
가중은 자세 루프 대역폭 ~6 Hz인데, 업데이트 지연 + wrench 실현 지연에서 위상여유가
안 남는다. **해법: Q_Θ=10, Q_ω=5로 낮춰 ~2 Hz 대역폭 + MPC 100 Hz.**
가중치 튜닝은 "적당히"가 아니라 **대역폭 추정**으로 접근할 것:
`ω_n ≈ (q_θ/r_eff)^(1/4)/√I`.

### (4) pelvis 각속도 ≠ SRB 각속도 — 제일 중요한 발견
(3)까지 고쳐도 밀기만 하면 넘어졌다. 로그를 보니 push 직후 10 ms 만에
wy가 −0.06 → **+0.85 rad/s** 점프 — 강체 회전이면 292 N·m가 필요한데 당시 토크는
14 N·m. 즉 **측정이 이상한 것**: ω를 pelvis(free joint qvel)에서 읽고 있었는데,
외란이 "다리 서스펜션 위에 얹힌 골반"의 내부 진동 모드를 때리면 골반만 고주파로
흔들린다. SRB 모델은 이걸 몸 전체 회전으로 착각 → 과반응 → 진동 증폭 → 발산.
단서: CoM 속도(vx)는 처음부터 전신 값(subtree_linvel)이라 매끈했다.
**해법: SRB 정의 그대로 ω = I_w⁻¹·L (전신 각운동량, MuJoCo subtree_angmom).**
내부 모드가 평균화되어 사라진다. → `get_state(m, d, I_body=...)`
(적대적 검증 §4의 재기술: 이건 "ω가 못 본다"기보다 **"Θ(pelvis)와 ω(L)가 같은
강체가 아니다"** — 상태 안에 운동학 불일치가 내재한다. 걷는 동안 상시 작동하는
SRB의 구조적 결손이고, 상체 PD는 관측을 고친 게 아니라 로봇을 SRB에 강제한 것.)

교훈 요약: **모델–측정–비용이 한 세트다.** SRB로 예측하려면 상태도 SRB 정의로
측정해야 하고(4), 비용은 물리(중력 ff(1), 제약이 지켜주는 변수(2), 실현 지연(3))를
반영해야 한다. 그리고 이걸 전부 **로그가 찾아줬다** — x, u 로그 없었으면 (4)는
못 잡았다.

## 12. 디버깅 기록 (보행 편) — 6번 터졌다

**(1) swing 임피던스가 무르면 착지가 한 박자 늦는다.**
kp=350(고유진동수 1.3 Hz)으로는 0.2 s swing 궤적을 못 쫓아 발이 정점도 못 찍고
공중에 뜬 채 '스케줄상 착지 시각'을 맞는다 → MPC는 접지됐다고 믿고 300 N을 기대
→ 그쪽으로 툭 낙하 → 매 스텝 roll 킥 누적 → 발산. **kp=2500 (3.5 Hz)** 로 해결.

**(2) 다리를 던지면 상체가 반대로 돈다 (고양이 회전).**
swing 반작용으로 골반 pitch가 0.2 s 만에 +21.9° — 그런데 각운동량 기반 ω는 ≈0.
내부 운동은 L에 안 잡히므로 **MPC의 ω는 이 회전을 정의상 못 본다** (Θ 피드백만
남음). 대책 둘: ⓐ **상체(허리+팔 17관절) 자세 PD** — 중력보상만 받던 상체를 고정해
로봇을 SRB 가정에 가깝게 만듦. ⓑ swing 힘 상한. roll 은 발볼 반폭 2.5 cm 라 발목 권한이 ~8 N·m 뿐이라 특히 취약했다.
(정정: 초판에 'I_xx=0.54 로 작아서'라 썼는데 0.542 는 I_zz(요)다. I_xx=3.55.
롤 취약의 원인은 관성이 아니라 발목 권한 — 적대적 검증에서 잡힌 오기.)

**(3) 착지점을 현재 CoM 기준으로만 잡으면 발디딤이 표류를 못 잡는다.**
CoM이 옆으로 밀리면 발도 따라가서 아무것도 위치를 고정하지 않음 (y −0.155 까지
표류). 또 Raibert 원형 `v·T_st/2 + k·v` 는 속도계수 0.48 — 역진자 정답(capture
point) `1/ω₀ = 1/√(g/h) = 0.26` 의 2배라 **매 스텝 과잉 스텝 → 에너지 주입**.
→ [src/gait.py](src/gait.py) `raibert_target` 을 capture point 기반으로 재작성:
`p = CoM + offset + v_cmd·T_st/2 + (v−v_cmd)/ω₀ + k_a(anchor−CoM)` (y만 약한 앵커).

**(4) py 참조가 항상 중앙이면 MPC가 체중이동 없이 발목으로만 버틴다.**
지평의 접촉 스케줄로 지지 중심을 계산해 **sway 참조** (β=0.5) 를 넣음 — preview 가
있어야만 가능한 정석 체중이동. 이것까지 넣고 Step 5 통과.

**(5) 단, sway 참조를 스텝 함수로 넣으면 안 된다.**
접촉 전환 순간 참조 점프(0.06 m/0.04 s = vy_ref 1.5 m/s!)를 MPC가 쫓아 옆으로
차버림 → 1.5 s 만에 넘어짐. **속도 제한 램프(0.4 m/s)로 스무딩** 후 해결.
vy_ref 는 0 유지 (미분 넣으면 같은 문제).

**(6) 속도 한계 = massless-leg 가정이 깨지는 지점. ★ 논문감**
0.3 m/s 에서: swing 다리가 0.35 m 를 0.2 s 에 가야 해서 임피던스가 ~200 N —
그 반작용이 몸통(유효 ~28 kg)을 **−5 m/s² 로 제동** → vx 0.3→−0.1 붕괴 → 몸이
뒤로 기움 → G1 뒤꿈치가 5 cm 뿐이라 (my ≤ +0.05·Fz) 발목으로 못 잡고 후방 전도.
SRB(다리 무질량) MPC는 이 반작용을 원천적으로 모른다. **다리 질량 43%인 휴머노이드
에서 convex MPC의 속도 한계가 실체로 나타난 것 — residual RL이 메울 gap 그 자체.**
당장의 우회는 감속(0.15 m/s)뿐.
(이 진단은 처음엔 로그 해석뿐이었으나 §16의 격리 실험 — 다리질량 1/3 → 0.3 m/s
완주, swing 힘 상한 400 N → 무효 — 으로 인과가 확정됐다.)

**(7) 착지점 '위치' 피드백의 부호 — 사용자의 quadruped MATLAB 코드가 정답을 줬다. ★**


## 16.1 ★ 확정 버그: CoP 제약의 h 결합항 누락 → 수정 + 완전 검증

```
m_ground,y = my + h·Fx,   m_ground,x = mx − h·Fy      (h = h_sole = 0.035, 모델 추출)
```

- yaw≠0 잠복 버그(제약이 world x=앞 가정)도 같이 수정: `C·(Rz(ψ)ᵀW) ≤ d`

## 16.4 반영한 사소 수정 일괄

- **이산화**: Euler → 정확한 ZOH `A_d = I + A·dt + ½A²dt²` (A 멱영이라 닫힌 형태)
- **k=0 선형화**: 지평 첫 스텝 r 을 참조가 아닌 **현재 상태** CoM 기준으로 (Di Carlo /

- **stage-0 접촉**: `contact[0] = in_stance(t)` (중점 t+25ms 는 착지 25 ms 전부터

- **I_body 프레임**: 추출 시 Rz(ψ₀)ᵀ 로 body frame 저장, `get_state` 가 현재 yaw 로

## 16.5 리포트에 대한 반론 한 가지 (기록)

리포트 §5-(b)의 "swing 반작용을 d 항으로 SRB 동역학에 주입"은 **병진 채널에는
해당 없다**: 우리 상태 p·v 는 전신 CoM 이고, CoM 병진 `v̇ = ΣF_ext/M − g` 는 내부
운동과 무관하게 정확하다 (CoM 은 외력으로만 움직인다). 회전 채널도 CoM 기준
`dL/dt = Σr×F + m` 은 정확. swing 반작용이 실제로 새는 곳은:
1. **Θ(pelvis) 운동학** — Θ̇ ≠ Rz(ψ)ᵀ·(I⁻¹L) (§16.4 재기술의 그 불일치)
2. **토크 실현** — τ = qfrc_bias − JᵀW 의 준정적 가정이 swing 가속 중 깨져
   실현된 wrench ≠ 명령 wrench (0.3 m/s 로그에서 Fx 명령 +50 인데 vx 하락이 증거)

따라서 feedforward 는 SRB 의 d 항이 아니라 **실현 계층**(τ 에 swing 관성 보상항,
사실상 WBC-lite) 또는 Θ 운동학 보정에 넣어야 한다. 리포트 (c)의 "양극성(가속→감속)
패턴" 지적은 이 채널에서도 유효. → 다음 과제.

**채널 ①/② 분리 실험**과 **질량 스케일 곡선**.

## 17.1 채널 분리 실험 (리포트 §6) — 채널 ② 가 지배적

두 누수 채널: ① Θ(pelvis) 운동학 불일치, ② 토크 실현(τ=g−JᵀW 의 준정적 가정).
- (i) 상체 PD 강화 (kp 60→300): 채널 ① 억제
- (ii) `--swingid`: 채널 ② 보상 — **τ += M(q)·q̈_swing,des** (역동역학, 아래 17.2)

| vx | baseline | (i) 만 | (ii) 만 | (iii) 둘 다 |
|---|---|---|---|---|
| 0.25 | 6.5 s | 4.9 s ↓ | **20 s 완주** | **20 s 완주** |
| 0.30 | 6.4 s | 4.3 s ↓ | 16.9 s | **20 s 완주** |

- **채널 ② 지배 확정** — 역동역학 항 하나로 0.25 완주.
- (i) 단독은 오히려 악화 — 상체를 세게 굳히면 swing 반작용이 몸통에 더 직접 전달되는
  것으로 보임. 채널 ① 은 (ii) 와 결합해야 이득.
- **(iii) 판정 기준 충족**: 원래 다리 질량으로 0.3 m/s 완주 = 1/3 질량 성능 재현.
  → massless-leg gap 의 대부분은 **결정론적 보상으로 메워진다.**

## 17.2 WBC-lite baseline (`09_walk.py --swingid`)

```
τ = qfrc_bias + M(q)·q̈_swing,des − Σ_stance JᵀW + swing 임피던스 + 상체 PD
```
- q̈_swing,des: swing 궤적의 **해석적 가속도**(smoothstep 2계도함수 — 양극성이 자동으로
  담김, 리포트 (c) 충족)를 다리 6×6 자코비안 역으로 관절가속으로 변환
- M(q) 밀집 → **stance·base 관절에도 보상 토크**가 들어가 "실현 wrench ≠ 명령 wrench"
  누수를 막음 (이게 Jᵀ 임피던스만으로는 안 되는 부분)
- 근사: J̇q̇ 생략, ‖q̈‖ ≤ 300 클램프 (특이자세 보호)
- 구현 주의: MuJoCo 3.12 는 `mj_fullM(m, d, dst)` (구버전 `(m, dst, d.qM)` 아님)

## 17.3 새 속도 한계 + 질량 스케일 곡선 (논문 그림 데이터)

**(iii) 구성 속도 스윕**: 0.30 완주 / 0.35 → 10.7 s / 0.40 → 3.6 s
→ **벽이 0.15 → 0.30~0.35 로 2배 이상.** 회귀: 제자리·0.15 40 s 전부 통과.

**질량 스케일 곡선 (baseline, vx=0.3, 20 s)** — 리포트 §3 요구, 4점 완성:

| 다리 질량 배율 | 0.33 | 0.50 | 0.67 | 1.00 |
|---|---|---|---|---|
| 결과 | 완주 | 완주 | 8.9 s | 6.4 s |

단조 — "벽이 다리 질량에 비례해 밀린다"가 그래프 한 장으로 성립.

## 17.4 residual RL 에 주는 함의 (논문 서사 확정)

- 정직한 baseline 완성: **MPC + WBC-lite (결정론적)** 가 0.3 m/s 까지 감.
  residual RL 은 이것을 이겨야 한다 — "SRB 만 놓고 RL 이 메웠다"는 약한 주장 차단.
- RL 이 메울 **잔여 gap** 도 구체화됨: 0.35+ 속도, J̇q̇·모델 오차, 접촉 타이밍 적응,
  채널 ① 의 원리적 해결 (지금은 상체 PD 밴드에이드).
- 리포트 §5 지적대로, 이 구조는 재현 논문(Jeon)의 τ = τ_MPC + λ·τ_res 와 정확히
  같은 토크 레벨 — residual 이 자리 잡을 채널이 실험으로 식별된 셈.

# 18. 회전(yaw) 보행 진단 테스트 (2026-09-11)

**목적**: 회전을 제대로 구현하기 전에, 현 구조 그대로 요 명령을 넣어 **어디서 깨지는지**
확인. 제약/선형화의 yaw 고정 문제는 일부러 두고(선형화만 지평 평균 yaw 로) 최소 변경.

구현: `--wz <rad/s>` — 요 각속도 명령을 적분해 yaw 참조 생성, v_cmd 를 body→world 회전,
X_ref 의 yaw·wz 채움. [src/09_walk.py](src/09_walk.py) `yaw_ref`, `wz`, `v_cmd`.

## 18.1 결과

**제자리 회전** (WBC-lite + 상체PD 300, 15 s):

| wz 명령 | 결과 | 달성 wz | yaw 오차 |
|---|---|---|---|
| 0.1 | **완주** | 0.087 | −1.7° |
| **0.2** | **완주** | 0.165 | −11.3° |
| 0.3 | 12.3 s 전도 | — | — |
| 0.4 | 8.0 s 전도 | — | — |
| 0.5 | 10.5 s 전도 | — | — |

**전진 0.15 + 회전**: 0.1 에서 11.3 s, 0.2 에서 8.1 s, 0.3 에서 7.6 s — **전부 전도**.
직진 단독(40 s 완주)·회전 단독(0.2 완주)은 되는데 **조합이 더 어렵다.**
(baseline: 보상 없이 wz=0.2 는 6.3 s 전도 → WBC-lite 는 회전에도 도움이 됨)

→ **현 구조의 회전 한계: 제자리 0.2 rad/s (≈11°/s), 전진 동반 시 사실상 0.**

## 18.2 원인 두 가지 — 로그에서 확정

### (a) ★ mz 무제약 — QP 가 물리적으로 불가능한 비틀림을 명령

wz=0.3 실패 로그의 요 모멘트: **|mz| 평균 5.3, 최대 143 N·m**.
G1 발은 접촉 구 4개(17×5 cm)라 지면 비틀림 권한은 μ·Fz·(유효반경) ≈ **수 N·m** 수준.
143 N·m 는 **물리적으로 실현 불가** — MPC 는 "이만큼 비틀겠다"고 계획하지만 지면이
못 주므로 실현 wrench ≠ 명령 wrench → 요 추종 실패 → 자세 붕괴.

직진에선 mz≈0 이라(R 벌점만으로 충분) 안 터졌던 것. **회전은 mz 를 실제로 써야 하는
동작이라 무제약의 대가가 즉시 나타난다.** → Caron CWC 의 mz 결합식 필요 (OA-MPC 식 12).

### (b) ★ 마찰 사각뿔 근사가 회전에서 물린다

같은 로그에서 **|F_xy|/Fz 최대 0.849 = √2 × 0.6**.
우리 제약은 `|Fx| ≤ μFz` **및** `|Fy| ≤ μFz` (사각뿔)인데, 이건 원뿔의 **외접**
근사라 **대각 방향에서 √2 배(41%) 낙관적**이다.
- 직진: Fy 가 작아 대각에 안 감 → 무해했음
- 회전: Fx·Fy 를 **동시에** 쓰므로 정확히 대각 → 41% 초과 → 실제로는 **발이 미끄러짐**

PHYSICS_MAP §6 에 "무해"라고 적었던 근사 ④ 가 **회전에서는 유해**로 바뀐다.
→ 수정: 사각뿔을 **내접**으로 바꾸거나(μ→μ/√2, 보수적), 8각뿔로 세분.

## 18.3 부차 관찰

- 요 추종 자체가 느리다: 0.1 명령에 0.087 달성(87%), 0.2 에 0.165(83%).
  Q_yaw=20 인데 요 관성 I_zz=0.542 로 제일 작은 축이라 대역폭은 충분할 것 —
  권한 부족(mz 실현 불가)이 원인일 가능성이 높다.
- 전진+회전이 더 어려운 이유(추정): 진행방향이 계속 돌아 착지점 계산의 side_offset
  회전, sway 참조 방향, 제약 frame(yaw₀ 고정!) 이 전부 어긋난다. §18.4 참조.

## 18.4 아직 안 고친 것 (회전 제대로 하려면)

1. **mz 제약 (Caron CWC)** — (a) 의 직접 해결. 최우선.
2. **마찰 내접/8각뿔** — (b) 의 직접 해결. 한 줄.
3. **제약 frame 이 yaw₀ 고정** — `foot_constraints(psi=psi0)` 를 생성자에서 한 번만
   호출. 몸이 90° 돌면 "발가락 방향" 제약이 완전히 어긋난다. 발별 `site_xmat` 또는
   최소한 현재 yaw 로 매 스텝 재생성 필요.
4. 지평 내 발 위치가 회전을 반영 안 함 (착지점은 yaw 를 받지만 foot_traj 는 계획 고정)
5. hip_yaw 관절 활용 — 지금 발은 몸과 같이 도는데, toe-out 을 허용하면 요 권한이 늘어남

**결론**: 회전은 "코드 수정 거의 없음"으로 시험은 됐지만, **제대로 하려면 mz 제약과
마찰 근사부터 고쳐야 한다.** 두 개 다 선형이라 QP 구조는 그대로 유지 가능.

## 18.5 mz 제약 구현 — 선 접촉 실패 → Caron 사각 정확식 (2026-09-11)

**1차 시도 (OA-MPC 식 12, 선 접촉)**: 뒤꿈치/발가락 2점 분해 → mz 4행. 유도 자체는
검증 통과(2점 모델 대비 100%)했으나 **직진 보행이 무너졌다** (0.15 가 7.6 s 전도).
로그 진단: mz1/mz2 행 활성률 42~45% — 선 모델은 횡력 Fy 를 뒤꿈치/발가락 fz 배분에
묶는데, 실제 사각 발은 너비(±w)로 Fy 를 감당한다. **점 2개 모델이 sway 용 Fy 를
과하게 조인 것.** 교훈: "보수적 근사는 안전하다"는 방향이 맞아도 **얼마나** 보수적인지가
문제 — 여기선 보행에 필수인 힘 채널을 잘랐다.

**2차 (Caron ICRA'15 사각 접촉 CWC 정확식, 8행)**:
```
중심 기준 (X=(lt+lh)/2=0.085, Y=w=0.025, x_c=(lt−lh)/2=0.035):
  τx = mx − h·Fy,  τy = my + h·Fx + x_c·Fz,  τz = mz − x_c·Fy
  τz ≤ μ(X+Y)Fz − |Y·Fx + μτx| − |X·Fy + μτy|      (+ 대칭 하한) → |·| 전개 8행
```
- 부호는 기억이 아니라 **LP 피지빌리티 3000샘플 대조로 확정** (100% 일치)
- 단위테스트를 LP 기반으로 재작성: **전체 18행 = 4점 사각 접촉 LP 와 100% 일치**
  (2500샘플 × yaw 0/0.7, [src/10_constraint_check.py](src/10_constraint_check.py))
- 검증 함정 재발 주의: 점힘 샘플의 "그 배분이 위반" ≠ "wrench 가 실현 불가"
  (Fx 배분은 자유) — 정답 판정은 LP 존재성으로 해야 한다.

## 18.6 회전 재시험 + 발/몸 frame 분리 발견

mz 제약(Caron) 후 제자리 회전:

| wz | 이전 (mz 무제약) | mz 제약 후 |
|---|---|---|
| 0.1 | 완주, 오차 −1.7° | 완주, −0.8° |
| 0.2 | 완주, **−11.3°** | 완주, **−1.4°** (추종 대폭 개선) |
| 0.3 | 12.3 s | 14.0 s (여전히 전도) |

계획이 물리 한계(|mz| ≲ 6 N·m) 안에 있으니 실현이 따라와 추종 정확도가 크게 좋아졌다.

**frame 실험에서 나온 발견**: 제약 frame 을 몸 yaw 로 돌렸더니 오히려 악화(15 s 완주
→ 12.4 s). 이유 — **stance 발은 착지 방향으로 땅에 박혀 있고 몸만 돈다.** 게다가
swing 발 자세 제어가 "발바닥 수평"만 잡고 yaw 는 자유라, **발이 몸을 따라 돌지 않는다**
(hip yaw 가 감기며 12~15 s 에 전도 — 회전 지속 실패의 메커니즘). 수정:
1. 제약 frame = **발별 실제 site yaw** (`psi_feet`)
2. **swing 중 발 yaw 정렬**: 목표 방향으로 z축 스프링 (`yaw_des`)
둘 다 **회전 명령이 있을 때만** 적용 — 직진에선 발 yaw 잔진동/정렬 토크가 marginal
한 0.3 m/s 를 흔들었다 (게이트 이유).

## 19. reference 분석 이식 1차 — 회전 벽 붕괴 (2026-09-15)

[ispaik06/convex-mpc-biped](https://github.com/ispaik06/convex-mpc-biped) 를
`reference/` 에 clone 해 분석([REFERENCE_ANALYSIS.md](../REFERENCE_ANALYSIS.md)) 후,
이식 후보 1·2번 + 랩 버그 수정으로 **제자리 회전 한계가 0.2 → 1.0+ rad/s** 가 됐다.

### 19.1 이식한 것 (전부 wz≠0 게이트, 직진 경로 불변)

1. **stance 발 yaw 유지 모멘트** (`KP_YAWHOLD=100, KD_YAWHOLD=10`):
   착지 순간의 발 yaw 를 기록, stance 중 world-z 모멘트 PD 를 J_ωᵀ 로 인가.
   hip_yaw 가 발 미끄럼(감김)을 능동적으로 막는다. MPC wrench 밖의 추가 채널.
   `--noyawhold` 로 끌 수 있음.
2. **착지 발 사전 회전**: raibert 의 공칭 오프셋 회전 yaw 를 측정 yaw 가 아니라
   **착지 시점의 참조 yaw** `yaw_ref(t + time_to_touchdown)` 로.
3. **swing 발 yaw 도 착지 시점 겨냥** + **회전 안쪽 발 toe-in 바이어스**
   (reference SwingYawTarget: 100°/(rad/s), 최대 20° — +wz 면 왼발).
4. **측정 yaw 언랩** (19.2 — 게이트 없음, wz=0 에선 수치 항등).
5. **전진+회전 조합의 원호 참조**: X_ref 위치·속도를 회전하는 명령속도의 적분
   (원호)으로, sway 중앙도 원호 위의 y 로. raibert 의 y 앵커(초기 y₀ 고정)는
   조합에서 해제 — 직선 전제라 원호 경로를 이탈시키는 원인이었다 (±34 cm 발산 실측).

### 19.2 ★ 랩 버그 — "0.3 rad/s 벽"의 진짜 정체

측정 yaw 는 atan2 (±180° 랩), 참조 yaw 는 무한 적분. **참조가 180° 를 넘는 순간
MPC 가 −360° 오차를 보고 폭주**한다. 붕괴 시각이 정확히 일치했다:

## 20. "상체만 SRB" 검토 — MIT humanoid vs G1 다리 질량 (2026-09-15)

**질문**: MIT humanoid 데모(몸통이 거의 고정된 듯 걷는)가 상체만 SRB 로 잡아서인가?
다리 무시의 타당성이 다리 질량 비율에 달려 있다면 G1 은 몇 % 인가?

**답 — 비율은 거의 같고, 분포가 다르다** (MIT: [mit-biomimetics/fld](https://github.com/mit-biomimetics/fld)
공개 URDF, G1: 우리 menagerie 모델에서 직접 계산):

| | G1 (23dof) | MIT humanoid |
|---|---|---|
| 총질량 | 33.34 kg | 24.25 kg |
| 다리 한쪽 | 7.19 kg | 5.30 kg |
| **양다리 비율** | **43.1 %** | **43.7 %** ← 사실상 동일! |
| **무릎 아래 (한쪽)** | **2.61 kg** (정강이 1.93 + 발목 0.68) | **0.63 kg** (4.2배 차이) |
| 다리 1차 질량모멘트 m·d (힙 기준) | ≈ 2.07 kg·m | ≈ 0.92 kg·m (근사*) |
| 무릎 아래 m·d | 1.34 kg·m | 0.34 kg·m |

*MIT 힙 모듈에 경사 축(rpy)이 있어 cm 수준 근사. 자릿수는 신뢰 가능.

해석:
- "MIT 는 다리가 가벼워서"는 **비율로는 틀리고 분포로는 맞다**. swing 반작용은
  링크 CoM 의 가속 × 질량인데, 가장 빨리·멀리 움직이는 건 원위(무릎 아래) —
  거기가 4배 가볍다 (설계 철학: 구동기를 힙에 모으고 링크로 전달).
- 결정적 실증: **reference 저장소가 같은 G1(43%)을 상체만 SRB 로 0.6 m/s /
  1.3 rad/s 로 걷게 한다.** 즉 상체만 SRB 는 G1 에서도 성립하되, 조건이 있다 —
  **swing 다리가 자기 동역학을 스스로 보상**(다리 질량행렬 + 중력 bias 보상,
  고대역폭 OSC)해야 한다. 다리를 모델에서 빼는 것과 다리를 방치하는 것은 다르다.
- 우리 --legmass 실험(다리 가볍게 → 벽 소멸)과 일관: 문제는 "다리 질량이 모델 밖"
  이 아니라 "모델 밖인데 보상도 안 됨"이었다. 상체만 SRB 로 가면 Θ·ω 불일치
  (§4, "같은 강체가 아니다")도 함께 해소된다 — 모델도 상태도 상체로 통일되므로.
- 이식 시 주의 (REFERENCE_ANALYSIS 8절 #7): MPC 질량이 19 kg(상체)이 되면 공칭
  Fz 합도 ~190 N 으로 줄어든다. stance 다리 자중은 wrench 가 아니라 구조/bias 로
  흘려보내는 그림 — 우리 τ = qfrc_bias − JᵀW 파이프라인과의 정합은 실험으로 확인 필요.

## 21. 상체만 SRB 실험 — 부정적 결과와 그 기전 (2026-09-15)

코드: [src/11_walk_srb_upper.py](src/11_walk_srb_upper.py) — 09_walk 에 SRB 재료
훅 2개(make_srb_params / get_state)를 뚫고, 그 둘만 재정의하는 서브클래스.
**두 파일의 diff 가 곧 "전신 SRB vs 상체 SRB"의 개념 차이**가 되게 설계.
러너 재사용(ctor 주입), 로그는 walk_upper_* 로 분리.

### 21.1 v1 — 병진까지 상체로: 물리 발견 2개를 낳고 실패

설계: 질량 18.97 kg(상체), p·v = 상체 CoM(subtree 빼기 항등식), ω = pelvis.

**발견 1 — 다리는 wrench 뒤에 '전부' 매달린다.** 골반이 0.76→0.58 m 주저앉음.
swing 다리만 보정(g·(1+0.5·m_leg/M_ub))했더니 절반만 회복. 로그 진단: 명령
ΣFz 319 N ≈ 전신 무게. 원인은 우리 stance 사상 τ = qfrc_bias − JᵀW 가
정역학에서 **접촉력 = W 를 정확히 실현**한다는 것 (Step 1 검증 성질의 이면).
접촉력이 W 로 고정이면 stance 다리 무게도 '구조'가 아니라 W 가 진다:
    올바른 유효 중력 = g·M_tot/M_ub  (17.24 m/s²)
이 보정으로 높이 완벽 유지, 제자리 12 s 통과. ↔ reference 는 stance 에 bias 를
안 넣어 접촉력이 W+다리무게로 자기증강 → 그쪽 W 는 상체 몫만 짐.
**bias 유무가 두 설계의 갈림길** — 같은 "상체 SRB"라도 토크 사상에 따라
유효 중력이 달라진다.

**발견 2 — 병진은 뉴턴이 정확하다.** 전진 램프에서 즉시 전도 (0.3: 4.4 s,
vx +0.21→−0.53 요동). B 의 수평 응답 1/M_ub 는 실제(LIP 시간스케일에선 다리도
함께 가속 ≈ 1/M_tot)보다 1.76배 과민 → 속도 루프 게인 뻥튀기.
M_tot·v̇_CoM = ΣF − M_tot·g 는 다리 포함 **정확** — 병진까지 상체로 바꾸는 건
정확한 식을 일부러 틀리게 만드는 것이었다.

### 21.2 v2 — 회전만 상체 + 절단 격자 (직진 0.3, 20 s 목표)

v2: 병진 전신 유지, I_body ← 상체(I_xx 3.55→0.74, I_zz 0.54→0.28), ω 선택제.

|---|---|---|---|

| **upper** | 4.5 s — ω 둔한데 모델 민첩, vx 0.60 오버슛 | 13.5 s, y ±15.2 cm roll 과반응 | 4.3 s — 가장 매끈(±1.3 cm)하나 yaw −13° 표류 후 전도 |

회전 도메인(가벼운 I_zz 가 유리해야 할 무대)에서도: wz=1.3 baseline 완주(−0.8°)

### 21.3 결론 — '무거운 모델'은 우연이 아니라 필터였다

1. **일관성이 지배 변수**: (Θ, ω, I) 를 섞으면(전신 I+pelvis ω 등) 즉사하고,
   일관 쌍끼리 비교해야 의미가 있다.
2. 그중에서도 **baseline(전신 L·전신 I)이 전 영역 우세**: 다리 43%의 스윙
   반작용 모멘트가 상체-회전 모델에선 전부 비모델 외란인데, 전신 L·I 는 그
   반작용을 L-공간에서 암묵 흡수한다 (다리가 앞으로 차면 L 은 그대로, 분배만
   바뀜 → ω 상태가 요동하지 않음). Θ/ω 불일치(§4)는 이 흡수의 '대가'였고,
   값을 치를 만한 거래였던 것.
3. reference 의 상체 SRB 성공은 모델 단독이 아니라 **패키지**: 위치 가중치
   ~840배(py 42000 vs 50) + Λ-스케줄 고강성 스윙 OSC(반작용 자체를 축소).
   상체 SRB 를 이식하려면 그 전제(스윙 대역폭·가중치 재설계)부터 — 종속성 확인.
4. 논문 서사: "SRB 의 몸을 무엇으로 잡을지는 컨트롤러 패키지와 분리 불가"
   — 그리고 남는 반작용이 residual RL 이 메울 gap 이라는 논지로 연결 가능.

파일은 절단 실험 장비로 보존: `--isrc {upper,full} --wsrc {pelvis,angmom,angmom_ub}`.

## 23. 흔들림 개선 1차 — 착지속도 0 + Λ 스케줄 스윙 (2026-09-15)

Q&A Q3 의 우선순위 1·2 를 각각 플래그로 구현, 격리 검증 후 결합 (120 초 기준).
코드: [gait.py](src/gait.py) `soft_land`/`v_td`/`kp_axis·kd_axis`,
[09_walk.py](src/09_walk.py) `--softland --lamswing --wn --zeta`.

### 23.1 구현

**A. `--softland` (착지 수직속도 0)**: 스윙 z 를 sin 아치(착지 시 v_z=−0.785 m/s
로 내리꽂음) → 2단 프로파일로. 전반 smoothstep 상승(z_mid), 후반 Hermite 하강
(끝 속도 −v_td, 기본 v_td=0). xy 는 원래 smoothstep 이라 끝 속도 이미 0.

**B. `--lamswing` (Λ 스케줄 스윙 게인)**: kp = ω_n²·diag(Λ), kd = 2ζ·ω_n·Λ,
Λ = (J M⁻¹ Jᵀ)⁻¹ (겉보기 관성, 매 틱 계산). 힘 상한 200→400 N (고강성에서
200 은 상시 포화). **채택값 ω_n=30, ζ=0.7** — x 는 현상 유지(kp≈1900), z 만
3.7배 강화. 수직 등가 대역폭 15.6 → 30 rad/s.

### 23.2 튜닝 과정에서 배운 것 (실측)

1. **ω_n=100 (reference 값) 은 우리에게 과하다**: kd 고정 시 ζ≈0.04 저감쇠 →
   스윙 5 cm 명령이 22 cm 오버슛, 11 s 전도. kd 스케줄(ζ=0.5) 후에도 8 s 전도
   (±16 cm) — **고강성 스윙은 반작용 증폭기**: 몸이 흔들리면 발 상대오차가
   생기고 고게인 힘이 그 오차에 반응해 몸을 되민다. reference 가 버티는 건
   원위 다리 4배 가벼움 + 위치 극단 가중 MPC 덕 (21절과 같은 '패키지' 교훈).
   ω_n=50 도 전도. **30 이 우리 경계 안**.
2. **lamswing 단독은 전멸** (제자리 15 s / 0.15 9 s / 0.3 6 s): sin 아치의 착지
   v_des=−0.785 를 고감쇠 kd_z=433 이 증폭 → **착지마다 ~340 N 으로 땅을 찍음**.
   즉 B 의 실패 원인이 정확히 A 가 고치는 결함 — **soft_land 는 lamswing 의
   전제조건**이었다. "둘 다 좋으면 합치기"가 아니라 "합쳐야 B 가 사는" 구조.
3. **v_td=0.1 ('지그시 누르기', 논문 식 15 방식) 은 양쪽 다 손해**: 제자리
   pitch 안 돌아오고(3.3° vs 3.6°) 0.3 완주가 4.6 s 전도로 붕괴. 저속 pitch
   후퇴의 원인은 착지 타이밍이 아니라 **하중 이전 지연** 자체 — 접촉 인지
   계층(wrench 램프·조기접촉 승격, reference ContactManager)의 몫. 기본 0 유지.

## 24. 속도 벽 돌파 — 0.3 → 0.5 m/s (2026-09-15)

계기: **"reference 는 같은 G1 으로 0.6 m/s 를 하는데 왜 우리는 안 되나. residual RL 로
미루지 마라 — 논문 저자의 convex MPC 자체가 1.5~2 m/s 다"** (사용자 지적).
타당한 지적이었고, 이전 23절의 "발이 작아서 CoP 가 모자란다"는 **틀린 결론**이었다
(reference MIT 는 `half_length 0.065 / half_width 0.01` 로 **우리보다 작은 발**로 1~2 m/s).

### 24.3 채택한 두 변경 (같이 가야 함)

### 24.5 실패한 시도 (기록)

- **주기 단축** (0.8→0.65/0.5/0.4 s): 전부 악화 (0.65 부터 전도). 보폭은 줄지만
  스윙이 다시 빨라져 반작용 증가 — 다리가 무거운 우리에겐 역효과.
- **LIP 스텝간 정확해** (`--lip`): 유도상 우리 중립항 `v·T_st/2` 는 정확해
  `(v/ω₀)tanh(ω₀T/2)` 보다 **25~42 % 과대**(발을 너무 앞에 놓아 제동)인데,
  적용하니 **오히려 추종 악화** (0.5: 0.50→0.18, 0.6: 0.48→−0.01).
  우리 계는 수동 LIP 이 아니라 MPC 가 능동 제어하고, 나머지 튜닝이 기존 공식에
  co-adapt 돼 있어서. 플래그로만 보존, 기본은 기존식.
- **자세 가중치 10→200**: pitch −19.7°→−0.8° 로 기울기는 고쳤으나 **속도는 불변**
  (0.17→0.18). 기울기는 증상이지 원인이 아니었다.

### 24.6 0.6+ 의 남은 벽 (성격이 다르다)

넘어지지 않고 **속도를 못 낸다**: 0.6 → 0.48 (79 %, CoP 41 % 포화),
0.8 → 0.17, 1.0 → 0.08. 0.8 이상에서는 CoP·스윙 모두 포화가 아닌데 ΣFx ≈ 1.3 N
— **MPC 가 밀지 않는다.** pitch −20° 로 기울어 SRB 소각 근사가 깨지는 영역.
