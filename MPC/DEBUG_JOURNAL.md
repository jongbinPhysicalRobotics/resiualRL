# 디버깅 기록 — MIT Humanoid convex MPC (2026-09-26 ~ 09-30)

> 목적 두 가지.
> ① 교수님께 **"왜 이렇게 바꿨는지"** 를 사례별로 설명할 수 있게: 증상 → 처음 가설 → 확인 방법 → 원인 → 해결 → 효과.
> ② 앞으로 새 문제를 만났을 때 **같은 방식으로 디버깅**할 수 있게: 원칙 · 기법 · 함정 · 도구.
>

## 2. 사례별 기록

### 사례 1 — OSQP 가 "수렴하지 못한다" (9/28 Q3 ~ Q5)

- **증상 (측정)**: 0.675 m/s 이상에서 넘어지기 직전에 OSQP 가 연달아 실패 → 재시도도 실패 → 비상용 해 (fallback: 수직력만, 수평력 0) → 발이 굴러 전도.
- **처음 가설**: 문제가 풀 수 없는 (infeasible) 상태가 된다.
- **확인 방법**: 실패한 QP 를 **저장**해서 정확한 풀이기 (quadprog) 로 다시 풀었다.
- **결과 → 가설 기각**: 전부 풀렸다 (제약 위반 1e-12). OSQP 도 350 ~ 625 회면 수렴했다.
- **진짜 원인** (측정 + 코드 사실):
  1. `slide` 설정에서 접촉 패턴이 매번 바뀌어 92 ~ 97 % 가 cold start (코드가 패턴이 바뀌면 warm start 를 버림).
  2. 행렬 조건이 나쁘다: P 고유값 0.002 ~ 12 000, 절반 (150 / 300) 이 정확히 2 × 입력 가중치 → "두 발 사이 힘 배분" 방향이 거의 평평.
  3. 종료 판정이 느슨해 "solved" 해도 정확해와 첫 스텝 힘이 110 N 다름.
  4. **ρ (ADMM 벌점) 기본 0.1 이 이 문제에 약 10⁴ 배 큼**: ρ 0.1 은 400 회를 돌려도 오차 133 N, ρ 1e-5 는 200 회에 1.8 N.
- **해결**: ρ 1e-5 → 고정 반복 + warm start (논문 방식) → 나중에 ρ 5e-5 · 10 ms (사례 7).
- **교훈**: "풀이기 실패" 를 보면 먼저 **문제 자체가 풀리는지** (정확 풀이기로) 와 **풀이기가 못 푸는지** 를 가른다. 그다음 조건수 · 스케일 · 시작점 (warm/cold) 을 본다.

### 사례 2 — 정확하게 풀면 오히려 넘어진다 (9/28 Q5 · Q6)

- **증상 (측정)**: quadprog (정확해) 는 제자리 회전 1.3 rad/s 에서 7.2 s 에 넘어지는데, OSQP (부정확) 는 버틴다.
- **해석**: 부정확한 해가 공식의 문제를 **우연히 가려** 주고 있었다.
- **확인 방법**: 원인 후보 7 개를 정확해로 15 s 씩 **하나씩 켜고 끄기**.
- **결과**: 착지 yaw 선행 (`swing_foot_yaw_lead_scale`) 을 끌 때만 통과. 1.3 rad/s 에서 착지 yaw 를 몸보다 41° 앞서 돌리고 있었다 (유도).
- **해결**: 선행 배율 0.5. 이후 회전 시험은 항상 **선행 0 / 0.5 / 1 세트** 로 (사용자 규칙).
- **교훈**: 풀이 정확도를 높였는데 나빠지면, 풀이기가 아니라 **공식** 을 의심한다. 후보를 나열하고 한 번에 하나만 바꾼다.

### 사례 3 — 0.6 m/s 의 칼같은 벽 (9/26 Q1 · 9/28 Q2)

- **증상 (측정)**: 0.600 ✓, 0.6001 ✗ — 너무 날카롭다.
- **해석**: 물리 한계라면 이렇게 날카로울 수 없다 → 코드 안의 **계단 (if 문)** 을 찾는다.
- **원인 (코드 사실)**: 착지 미리보기 k_half 가 속도 0.6 초과에서 0.37 → 0.28, 0.65 초과에서 0.26 으로 바뀐다 (reference 설정). 발을 덜 앞에 딛게 되어 과속 → 전도.
- **해결**: 속도와 무관하게 고정 (`khalf=0.37`, 이후 0.3).
- **교훈**: 어떤 값에서 **칼같이** 성패가 갈리면 연속적 물리가 아니라 코드의 분기 · 전환점을 찾는다.

### 사례 4 — 선 접촉 발 모델이 OSQP 에서만 틀린다 (9/28 Q10, 내 버그)

- **증상**: line (OA-MPC) 발 모델이 quadprog 로는 괜찮은데 OSQP 로는 이상 (회전에서 전도).
- **처음 가설**: 튜닝 부족 → 틀림.
- **확인 방법**: 같은 QP 의 **희소 (OSQP 용) 행렬과 조밀 (quadprog 용) 행렬을 원소 단위로 비교**.
- **원인 (코드 사실)**: 희소 패턴 표 (`_LINE_UNIT_COLS`) 에 발 좌표계 기준 열만 적어, 발 yaw 로 회전한 뒤 생기는 성분 360 개가 빠졌다 (yaw ≠ 0 일 때만 틀림).
- **해결**: 월드 좌표 기준 열로 수정, sparse == dense 검증. 이전 기록에 ⚠ 정정.
- **교훈**: 두 풀이기가 다른 답을 내면 **조립 단계 (행렬 만들기)** 부터 대조한다. 버그는 특정 조건 (여기선 yaw ≠ 0) 에서만 드러난다.

### 사례 5 — 회전 중 스윙 hip yaw 포화 (9/29 Q3)

- **증상 (측정)**: 회전 중 스윙 다리 hip yaw 명령 223 N·m (한계 34), hip abad 포화 51 %.
- **원인**: 스윙 발 yaw 목표를 착지 yaw 로 한 번에 줌 → 계단 입력을 딱딱한 자세 PD 가 따라가려 함.
- **해결**: 이륙 yaw → 착지 yaw 를 최소 저크 곡선으로 보간 + 명령 회전 속도를 앞먹임 (`yawtraj=1.0,yawff=2`). 223 → 15 N·m, 선행 0 / 0.5 / 1 모두 완주.
- **교훈**: 포화가 보이면 **어느 관절 · 어느 구간 (스윙 / 입각)** 인지부터 나누고, 목표가 계단인지 본다.

### 사례 6 — 걸으며 돌 때 바깥으로 밀림 (9/29 Q6 · Q7)

- **증상 (측정)**: 0.45 m/s 이상 + 회전에서 몸 기준 옆 속도가 −0.01 → −0.11 m/s 로 커지며 넘어짐. yaw 추종은 정상.
- **가설 ① 힘 부족 → 기각**: 안쪽 합력 8.3 N 은 필요량 (m·v·ω ≈ 2.7 N) 보다 크다.
- **가설 ② 경로 오차 적분이 잘못 당김 → 기각**: 경로 옆 오차는 5 cm 로 일정. 일정한 게걸음은 회전 중 옆 오차가 아니라 앞뒤 뒤처짐으로 나타난다 (유도).
- **원인 (코드 사실 + 추론)**: 착지점 주항이 **명령 속도 방향** 이라, 실제 진행이 뒤처지면 발이 진행선 안쪽에 놓이고 몸이 더 바깥으로 밀린다 (양의 되먹임).
- **시도**: 실측 속도로 바꾸기 (`vmeas`) → 회전은 되지만 곧은 걸음이 망가짐 (걸음 안의 속도 출렁임에 반응).
- **해결**: 크기는 명령, **방향만** 걸러진 실측 쪽으로 70 % 섞기 (`vdir=0.7`).
- **교훈**: 측정값을 되먹임에 넣을 때는 **걸음 주기 안의 출렁임** 을 먼저 생각한다. 필요한 성분 (방향) 만 거르고 섞는다.

### 사례 7 — 고정 25 회가 모자라다 (9/29 Q8 · Q10)

- **증상 (측정)**: 0.6 m/s + 0.5 rad/s 에서 25 회는 넘어지고 50 회 · 수렴 OSQP 는 통과. 그런데 75 · 100 회는 다시 넘어짐 (비단조).
- **확인 방법**: 걷는 중 QP 를 저장해 **반복 수별로 오프라인 재풀이** (`diag/iter_diag.py`, `iter_ana.py`).
  - 목적함수는 25 회에서도 정확해와 상대 1e-4 이하로 같다.
  - 달라지는 것은 **제약 위반** (25 회 중앙 0.81 → 50 회 0.35).
- **처음 추론**: 제약 위반 (비틀림 한계 초과) → 발이 돌아 전도.
- **개입 시험 → 추론 기각**: 제약을 좁혀 (µ 0.8 ~ 0.9, 비틀림 0.04 ~ 0.05) 위반이 실제 한계 안에 들게 해도 똑같이 넘어졌다. Q8 에 ⚠ 정정.
- **해결 (측정)**: ρ 3e-5 ~ 5e-5 + 풀이 주기 14 → 10 ms (논문과 같은 100 Hz) 로 25 회 통과.
- **교훈**:
  - 상관 (위반이 컸다) 을 인과로 쓰기 전에 **원인만 없애는 개입** 을 해 본다.
  - 파라미터에 대해 결과가 **비단조** 면 안정 경계 근처라는 신호다. 한 번의 결과로 결론 내지 않는다.

### 사례 8 — 측정 실수: 명령이 잘리고 있었다 (9/29 Q9)

- **증상**: "0.75 명령 → 실측 0.65, 천장 0.65" 라고 기록했다.
- **원인 (코드 사실)**: yaml `x_dot_max = 0.7` — 0.75 는 0.7 로 잘려 들어갔다. 회전도 `psi_dot_max = 2.0`, 옆은 `y_dot_max = 0.5`.
- **해결**: 전진 시험은 모두 `xmax=1.0`. 이전 기록에 ⚠ 정정.
- **교훈**: 명령과 실측을 비교할 때는 **제어기에 실제로 들어간 명령** (필터 뒤) 을 확인한다.

### 사례 9 — 0.8 m/s 에서 옆 속도가 남는다 (9/29 Q11)

- **증상 (사용자 렌더 + 측정)**: 몸 기준 vy −0.018 m/s 가 계속.
- **가설: 옆으로 흘러간다 → 기각**: 경로 옆 오차는 −6 cm 에서 늘지 않는다. 몸은 곧게 가고 **몸통만 1.3° 돌아가** 있다 (0.75 × sin 1.3° = 0.017).
- **확인 방법 — 거울 시험**: 좌우 걸음 위상을 맞바꾸면 (`sideswap=1`) vy, yaw, roll, 하중비가 **부호째 뒤집힌다** → 모델이 아니라 **어느 다리가 위상 0 이냐** 가 원인.
- **원인 (코드 사실)**: MPC 접촉표를 주기 시작점 기준으로 만들어 (O1), 두 다리가 받는 시간 어긋남이 다르다.
- **해결**: 접촉표 원점을 **반 주기마다** 옮김 (`fix=half`) → vy 0.000, 하중비 1.00, 맞바꿔도 결과 동일.
- **교훈**: 좌우 비대칭은 먼저 **맞바꾸기 시험** 으로 "위상 탓 / 모델 탓" 을 가른다.

### 사례 10 — 옆으로 밀면 발이 꼬인다 (9/29 Q12)

- **증상 (측정 + 사용자 렌더)**: 걷는 중 옆 20 N · 0.2 s 부터 위상에 따라 넘어짐. 밀린 직후 회복은 되는데 다음 걸음에서 두 발이 겹친다.
- **가설 ① 발 간격 부족 → 기각 (악화)**: 딛는 발과 최소 간격 강제 (`minw`) → 10/16 → 5/16. 밀린 쪽으로 딛는 회복 걸음을 막는다 (추론).
- **가설 ② 착지점이 이륙 때 고정이라 스윙 중 밀림에 반응 못 함 → 재계획 (`replan`)**: 걷기 시작 1 s 만에 발산.
  - **발산 원인 (측정)**: 첫 스윙 중 몸통 속도가 +0.15 → −0.35 m/s 로 뒤집힘 — 다리를 휘두른 반동. 착지점이 이를 따라 흔들리고, 발을 끌면 반동이 더 커지는 되먹임.
  - 몸통 속도엔 다리와 주고받는 운동량이 섞이고, **전신 CoM 속도엔 상쇄된다** (유도).
- **해결**: 착지점 계산에만 전신 CoM 속도 (`rvwb=1`) + 스윙 중 재계획 (`replan=1`, 착지 80 ms 전 고정 `rpfz=0.08`) → 옆 20 · 30 N 16/16.
- **교훈**:
  - 되먹임이 발산하면 **측정값이 제어 대상 자신의 움직임에 오염** 됐는지 본다.
  - 외란 시험은 **밀리는 순간의 걸음 위상** 을 여러 곳 (4 곳) 으로 바꿔 성공률로 잰다. 한 번의 결과는 위상 운이다.

### 사례 11 — slip 의 정체 (9/28 Q1 · 9/30 Q1 · Q10)

- **증상**: slip (입각 중 발 중심 이동) 8 ~ 15 mm, 뒤꿈치가 바깥으로 돌아 보임 (사용자 렌더).
- **확인 방법**:
  - 지표 정의를 **코드에서** 확인: 발 중심점 이동 거리.
  - 발 회전량과 비교: 75 mm × tan θ 가 측정 slip 과 거의 같다 → **앞꿈치 축 회전** 이 대부분.
  - 입각 구간별 프로파일 (`13_foot_diag.py --profile`): 입각 중반 뒤꿈치 하중이 0 에 가까울 때 MPC 가 yaw 모멘트 6 ~ 9 N·m 를 명령하고 그때 돈다.
- **시도**:
  - 선 접촉 제약 (비틀림을 CoP 에 묶음) → 거의 무효.
  - 딛는 발 yaw hold 끄기 → 회전 slip 은 사라지지만 **곧은 걸음 slip 24 mm 폭증** — hold 가 곧은 걸음의 발을 붙잡고 있었다는 발견.
- **근원 (측정 + 추론)**: 곧은 걸음에서도 스윙 다리 반동이 몸통을 매 걸음 ±0.25 rad/s 로 흔들고, 이를 딛는 발 비틀림으로 막는다.
- **해결**:
  - 팔 반대 흔들기 1.0 (`armsw`) → slip 절반 (0.8: 15.1 → 7.7 mm).
  - 사용자 요청으로 팔을 0.3 으로 되돌리고, 대신 딛는 발 yaw hold 이득 20 / 4 → 60 / 12 (`shkp`, `shkd`).
- **교훈**:
  - 지표 이름을 믿지 말고 **정의를 코드에서** 확인한다.
  - 기능을 **꺼 봐서** 그 기능이 무엇을 막고 있었는지 드러낸다.

### 사례 12 — 1 m/s 천장 (9/30 Q2 ~ Q5)

- **증상 (측정)**: 1.0 명령에 실측 0.87 m/s, 가끔 옆 휘청임.
- **확인 ① 관절 · 구간별 포화**: 스윙 다리 hip pitch 가 스윙 시간의 10.8 % 동안 한계 (72 N·m) 초과, 명령 최대 4 배. 딛는 다리는 여유.
- **가설 ① 스윙 시간이 너무 짧다** (보폭 / T² 가 논문의 3.5 배, 유도) → 스윙 · 주기 늘리기:
  - 그냥 늘리면 과속 전도 → k_half 를 유도식 k = (T_sw − δ)/T_st 로 맞춤 → 그래도 1.0 에서 전도.
  - 곁가지 발견: **예측 구간을 주기에 비례해 늘린 것이 전도 원인** 이었다 (0.44 s 고정해야 함).
  - 결과: 긴 주기도 천장 ≈ 0.88 → 기각.
- **가설 ② 가속 모양이 나쁘다** → 저가속 궤적 (`swprof`) → 1.0 악화 → 기각.
- **가설 ③ 관절별 자르기가 방향을 틀어 해롭다** → 비율 · QP 로 방향 보존 (`swlim`) → 1.0 악화 → 기각. "토크 부족 자체" 라고 결론 냈다 (이것도 틀림).
- **확인 ② 토크 성분 분해** (사용자 질문 "착지 속도가 영향을 주나" 에서 출발): hip pitch 토크를 앞먹임 · 되먹임 · 중력 · 발 자세로 나눔.
  - 착지 직전 **되먹임 (PD) 이 101 ~ 193 N·m, 앞먹임 (궤적 관성) 은 10 ~ 13 N·m**.
  - 발이 목표를 15 mm 지나치고 (오버슈트), 감쇠가 거의 없는 PD (ζ 0.03 ~ 0.16, K_d 25 고정) 가 이를 되돌리려 폭주.
- **해결**: 스윙 ω 0.46 배 + 감쇠비 0.7 (`swwn=0.46,kdz=0.7`) → 실측 0.96 m/s.
- **교훈**:
  - **큰 설계 변경 전에 신호를 성분으로 분해** 한다. 그럴듯한 물리 이야기 (토크가 원래 모자람) 가 틀릴 수 있다.
  - 이득 식에서 **유효 감쇠비** 를 계산해 본다. K_p 만 자세에 맞추고 K_d 를 고정하면 방향마다 감쇠가 제각각이다.

### 사례 13 — 고속에서 한쪽으로 쏠림 (9/30 Q7 · Q8)

- **증상 (측정 + 사용자 렌더)**: 0.9 ~ 1.0 m/s 에서 하중비 0.77 ~ 0.85, 몸통 −4°.
- **가설 ① 위상 → 기각**: 맞바꿔도 같다.
- **가설 ② 모델 비대칭 → 기각**: 몸통 무게중심이 y +4.8 mm (코드 사실) 인데, 가운데로 옮긴 진단 모델 (`symcom=1`) 에서도 같다.
- **가설 ③ 대칭 깨짐 (거울상 두 갈래 걸음)**: 초반에 반대로 세게 밀었더니 쏠림이 **뒤집혀 그대로 유지** (0.82 → 1.26).
- **기존 데이터 다시 캐기**: 스윙 게인 격자에 하중비 열을 붙여 보니, 감쇠비가 클수록 대칭, 쏠림 방향은 ω 에 따라 뒤집힘.
- **해결**: 감쇠비 1.2 (`kdz=1.2`) → 하중비 0.96 ~ 1.03, 밀린 뒤에도 대칭으로 복귀.
- **교훈**:
  - **반사실 시험** (모델을 대칭으로 고쳐 보기) 과 **교란 시험** (밀어서 다른 끌개로 보내 보기) 으로 "고정 편향 / 두 갈래" 를 가른다.
  - 이미 돌린 격자에 **다른 지표 열** 을 붙여 보면 새 실험 없이 단서가 나온다.

### 사례 14 — 팔을 줄이고 싶다 (9/30 Q10)

- **요구 (사용자)**: 팔 흔들기가 격하다.
- **측정**: 팔 1.0 → 0.3 이면 slip 0.8 m/s 17.7 → 27.4 mm, 0.5 이하는 1.0 m/s 에서 전도.
- **대체**: 딛는 발 yaw hold 60 / 12 → 걷기 slip 회복. 그러나 너무 세면 (≥ 80 / 16) 제자리 회전 악화, 60 / 12 도 2.5 rad/s · 선행 0 / 1 에서 전도.
- **해결**: 회전 명령 |ψ̇| 이 클수록 hold 를 reference 값으로 선형 보간 (`shw=2.0`) → 18 / 18 완주.
- **교훈**: 한 조건 (직진) 에 좋은 이득이 다른 조건 (회전) 을 해치면, 조건 변수로 **이득을 보간 (게인 스케줄링)** 한다.

## 3. 디버깅 방법 — 다시 쓰기 위한 정리

### 3.1 원칙

1. **증상을 숫자로 먼저 적는다.** "넘어짐" 이 아니라 "몇 초에, 어느 축이, 어떤 순서로".
2. **가설은 한 번에 하나, 반증 가능하게.** "무엇을 바꾸면 무엇이 달라져야 하는가" 를 미리 적는다.
3. **새 기능은 플래그로, 기본값 = 기존 동작.** 켠 것 / 끈 것을 같은 조건에서 A/B.
4. **판정 기준을 고정한다.**
   - 120 s 완주.
   - 표준 목표 세트 (전진 · 옆 · 회전 선행 0 / 0.5 / 1 · 걸으며 돌기).
   - 외란 격자 (교수님 지시).
   - 걸음 품질 표 (slip · 하중비 · 포화) + 렌더.
5. **60 s 로 선별하고 120 s 로 확정한다.** 경계 근처의 한 번 결과는 흔들린다.
6. **근거 종류를 밝힌다** (측정 / 코드 사실 / 유도 / 추론). 추론을 사실처럼 쓰지 않는다.
7. **틀렸으면 원래 기록에 ⚠ 정정** 을 달고 새 항목에서 바로잡는다 (이번에 4 번: 선 접촉 버그, 0.75 명령 잘림, 제약 위반 인과, 25 회 여유).

### 3.3 함정 — 이번에 실제로 밟은 것

- **명령 필터 상한**: `x_dot_max 0.7`, `y_dot_max 0.5`, `psi_dot_max 2.0` (yaml). 넘는 명령은 조용히 잘린다 → `xmax`, `ymax`, `wmax`.
- **계측이 시뮬을 바꾼다**: 진단 코드에서 시뮬 데이터에 `mj_forward` 를 부르면 궤적이 달라진다 → 복사본에서 계산.
- **동시 실행 중의 풀이 시간 (ms)** 은 부정확하다 → 비용은 단독으로 잰다.
- **지표 정의**: "slip" 은 발 중심점 이동이라 회전도 포함한다. 이름이 아니라 코드를 본다.
- **비단조 결과**: 25 ✗ / 50 ✓ / 75 ✗ 처럼 들쭉날쭉하면 안정 경계 근처다. 인접 조건을 더 본다.
- **예측 구간을 주기에 맞춰 늘리기**: 직관과 달리 전도의 원인이었다 (0.44 s 고정).
- **실행 중에 파일 고치기**: 이미 떠 있는 병렬 작업은 옛 코드를 쓴다 (모듈은 시작할 때 읽힘).

### 3.4 새 문제를 만났을 때 체크리스트

1. 증상을 재현하는 **가장 짧은 명령** 을 찾는다 (60 s, 명령 하나).
2. 명령이 실제로 들어갔는지 (필터 상한) 확인한다.
3. 시간 기록 (`diag/wt_diag.py` 류) 을 뜨고 **넘어지기 전 3 ~ 5 s** 를 걸음 단위로 본다: 무엇이 먼저 커지나.
4. 비대칭이면 → 맞바꾸기 시험. 포화면 → 관절 · 구간별 포화 + 토크 분해. 풀이기 의심이면 → QP 저장 · 재풀이.
5. 원인 후보를 목록으로 적고, 하나씩 **플래그로 켜고 끄는** A/B (60 s 선별).
6. 좋아 보이면 120 s + 표준 목표 + 외란 격자 + 걸음 품질로 확정.
7. Q&A 에 기록: 틀린 가설도, 근거 종류도.

## 4. 예시 스크립트 — 토크 분해 · 포화 비율 (사례 12 에서 쓴 것)

관절 · 구간별 포화 비율 (A16 설정을 넣으면 된다):

```python
# 저장소 루트에서: GAIT_ON=1 .venv/bin/python this.py
import importlib.util, sys, numpy as np, mujoco
sys.path.insert(0, "MPC/src/casadi_mit")
sp = importlib.util.spec_from_file_location("w", "MPC/src/casadi_mit/10_walk.py")
W = importlib.util.module_from_spec(sp); sp.loader.exec_module(W)
VAR = "…"                                   # --var 와 같은 변형 문자열
kw = W.parse_variant(VAR); prof = kw.pop("profile")
cfg, model, ctl, walk_t = W._setup(1.0, 0, 0, "osqp", True, prof, False, False, 1.0, True, False, **kw)
m, d = model.m, model.d
lim = model.ctrl_hi[model.leg_act].reshape(2, 5)
T, A = [], []
for _ in range(int((walk_t + 25) / m.opt.timestep)):
    tl, ta = ctl.tick()
    if d.time > walk_t + 8:
        T.append(np.abs(tl) / lim); A.append([ctl._active(l, ctl.state.t) for l in (0, 1)])
    model.write_torque(tl, ta); mujoco.mj_step(m, d)
T, A = np.array(T), np.array(A, bool)
for j, nm in enumerate(["hip_yaw", "hip_abad", "hip_pitch", "knee", "ankle"]):
    st, sw = T[:, :, j][A], T[:, :, j][~A]
    print(nm, "입각 p99", np.percentile(st, 99), "스윙 p99", np.percentile(sw, 99), "스윙 포화 %", 100 * np.mean(sw >= 1))
```

토크 분해는 같은 루프에서 스윙 다리마다 `leg_control` 의 식을 다시 계산한다:
앞먹임 = J_vᵀ Λ (a_des − J̇ q̇), 되먹임 = J_vᵀ [K_p (p_des − p) + K_d (v_des − v)], 중력 = bias, 발 자세 = 나머지.

## 5. 최종 설정 (A16) 과 각 키가 들어온 사례

| 키 | 사례 | 한 줄 |
|---|---|---|
