## Q1. Kp·Kd 구할 때 나오는 "ㅅ 모양 행렬" 이 뭐야?

**Λ (대문자 람다)** — 작업공간 관성행렬 (operational-space inertia). 코드에선

```
Λ = (J M⁻¹ Jᵀ)⁻¹        M = 관절공간 질량행렬, J = 발 site 야코비안
```

([09_walk.py](../MPC/src/09_walk.py) `torque()` 의 `lam_swing` 블록, reference 의 `OperationalSpaceDynamics` 와 같은 것)

### 1. 뜻 — 발이 그 방향으로 느끼는 무게

작업공간에서 `F = Λ ẍ` 가 성립한다. 발을 어느 방향으로 밀 때 다리 전체가 얼마나 무겁게 느껴지는지이고,
**자세에 따라 바뀐다.** 0.5 m/s 스윙 중 실측 (대각 성분):

| 스윙 진행도 | 앞뒤 x | 좌우 y | 위아래 z |
|---|---|---|---|
| 0.0 ~ 0.1 (이륙 직후) | 3.27 kg | 1.40 kg | 8.17 kg |
| 0.2 ~ 0.3 | 2.88 | 1.26 | 4.71 |
| 0.5 ~ 0.6 (중간) | 2.37 | 1.21 | 4.05 |
| 0.7 ~ 0.8 | 1.67 | 1.28 | 6.13 |
| 0.9 ~ 1.0 (착지 직전) | 1.34 | 1.41 | 10.25 |

위아래가 앞뒤의 3 배고, 한 스윙 안에서도 2.5 배 변한다 (다리를 펴면 무릎으로 밀어올리기 어려워짐).

### 2. 왜 게인에 곱하나

발 오차가 항상 같은 2 차 응답이 되게 하려면:

```
목표:      ë + 2ζω_n ė + ω_n² e = 0
필요 가속: a = ω_n² e + 2ζω_n ė
필요 힘:   F = Λ a = (ω_n²Λ) e + (2ζω_n Λ) ė
                      └ Kp ┘      └ Kd ┘
```

그래서 `Kp = ω_n²Λ`, `Kd = 2ζω_nΛ`. 우리는 ω_n 30 rad/s, ζ 0.7. 계산을 줄이려고 **대각 성분만** 축별로 쓴다.

**상수 게인이 안 되는 이유** (실측): kp 를 2500 N/m 로 고정하면 축별 고유진동수가
앞뒤 33 · 좌우 44 · **위아래 20 rad/s** 로 갈린다. 위아래가 제일 느려 발이 궤적을 못 쫓았다 (9/17 Q3 의 추종률 48 %).
Λ 스케줄이면 세 축 모두 30. 평균 게인은 `kp = [2035, 1175, 5789] N/m`, `kd = [95, 55, 270] N·s/m`.

## Q2. 그런데 Residual MPC 논문은 왜 훨씬 작은 고정 게인 (Kp 50, Kd 3) 으로도 잘 됐나?

> 판정: **비교 대상이 다르다.** ① 단위가 관절(N·m/rad) vs 발끝(N/m) ② 논문은 **PD 가 주역이 아니다** —
> RNEA 피드포워드와 **동역학적으로 맞는 관절 궤적**이 움직임을 만들고 PD 는 오차만 잡는다.

### 1. 단위를 맞추면 5 ~ 15 배 차이 (50 배가 아니다)

우리 발끝 게인을 관절 기준으로 환산 (`K_q = Jᵀ K_x J` 의 대각, 0.5 m/s 스윙 평균):

| 관절 | 우리 [N·m/rad] | 논문 [N·m/rad] | 비 |
|---|---|---|---|
| hip_pitch | 748 | 50 | 15 배 |
| hip_roll | 359 | 50 | 7 배 |
| knee | 249 | 50 | 5 배 |
| hip_yaw | 112 | 50 | 2 배 |
| ankle | ~0 | 50 | — (발 위치만 잡으니 발목엔 강성이 안 걸린다) |

감쇠도 같은 비율 (우리 hip_pitch 35 vs 논문 3 N·m·s/rad).

### 2. ★ 진짜 이유 — 논문의 PD 는 '보조' 다

논문 (Eq. 21):

```
τ_MPC = Kp(q_MPC − q) + Kd(q̇_MPC − q̇) + τ_RNEA
         └ 오차만 잡는 PD ┘              └ 원하는 운동을 만드는 역동역학 피드포워드 ┘
```

- **`τ_RNEA` 가 움직임을 만든다.** 원하는 관절 궤적의 관성·코리올리·중력을 전부 계산해 넣는다.
  피드포워드가 정확하면 PD 는 모델 오차만 메우면 되니 **작아도 된다.**
- **추종 대상 `q_MPC` 가 동역학적으로 맞는 궤적이다.** 논문 MPC 는 kinodynamic — 결정변수에 관절 궤적이
  들어 있어, MPC 가 다리 동역학과 접촉을 알고 만든 궤적을 PD 가 따라간다.

우리는 구조가 다르다 ([09_walk.py](../MPC/src/09_walk.py)):

```
스탠스: τ = qfrc_bias − JᵀW        (MPC 는 wrench 만 준다. 관절 궤적이라는 개념이 없다)
스윙  : τ = qfrc_bias + Jᵀ F_임피던스 + M q̈ (근사 피드포워드)
```

- **스윙에서 임피던스가 주역이다.** 발을 궤적에 붙여 두는 일을 스프링이 한다 → 세야 한다.
- **우리 피드포워드는 근사다.** `M q̈` 만 쓰고 `J̇q̇` 와 떠 있는 몸통과의 결합은 뺐다 (9/21 Q6).
  피드포워드가 부정확한 만큼 PD 가 더 일해야 한다.
- 우리 MPC 는 SRB 라 **스윙 다리 궤적을 모른다** — 그 궤적은 MPC 밖에서 기구학으로 만든 곡선이다.

### 3. 부차적인 차이

- **로봇 규모**: MIT 휴머노이드 약 25 kg, 다리가 가볍다. G1 은 33 kg 에 다리가 전체 질량의 43 %.
- **하나의 게인 세트로 통일**: 논문은 MPC · residual · end-to-end 가 **같은 게인**을 쓴다 (§V). 비교 공정성을 위한 선택이기도 하다.
- **residual 이 남은 오차를 메운다**: 접촉 전환 직전에 residual 토크 비중이 급증한다 (§V-D).
  단 **MPC 단독 기준선도 같은 작은 게인**이었으니, 작아도 됐던 주된 이유는 residual 이 아니라 피드포워드다.

### 4. 우리에게 주는 시사

1. **게인을 낮추려면 피드포워드를 정확하게** — 스윙 다리 역동역학을 제대로 넣는 것 (`J̇q̇` 포함, 몸통 결합까지).
   9/21 Q6 에서 `J̇q̇` 를 넣었더니 나빠졌는데, **그때는 이륙 첫 틱 버그(9/22 Q13)가 있던 상태**였다 → 재시험 가치 있음.
2. **ω_n 을 낮춰보는 것도 이제 다시 볼 만하다** — 버그 때문에 이륙마다 400 N 이 튀던 것이 사라졌으니,
   같은 추종을 더 무른 게인으로 얻을 수 있는지 (ω_n 30 → 20) 걸음 품질 표로 확인.
3. **residual 을 붙일 때**: 논문처럼 "MPC 가 쓰던 게인을 물려받기" 가 우리는 불가능하다 (다리 관절 PD 가 없음).
   우리 토크 스케일에 맞춰 새로 정해야 한다 (9/15 Q7).

## Q3. 우리 스윙 제어가 MIT Cheetah 3 convex MPC 논문 방식과 같은 건가?

> 판정: **같은 계열이고, 핵심 두 항은 수식까지 같다.** 우리가 reference 코드에서 가져온 게 이 논문 방식이다.
> 다른 건 ① `J̇q̇` 를 기본으로 생략 ② 발 자세 제어가 추가 ③ 조기/늦은 접촉 감지가 없음 ④ 스탠스는 6D wrench + 중력보상.

### 1. 항별 대조

| | 논문 (Cheetah 3, 식 1 ~ 4) | 우리 ([09_walk.py](../MPC/src/09_walk.py) `torque`, [gait.py](../MPC/src/gait.py) `wrench`) |
|---|---|---|
| 스윙 피드백 | `τ = Jᵀ[K_p(p_ref − p) + K_d(v_ref − v)]` | **같은 형태.** 단 그들은 몸 기준 frame, 우리는 월드 |
| 게인 스케줄 | `K_p,i = ω_i² Λ_ii` (식 3) | **같다.** 우리는 `K_d = 2ζω_n Λ` 도 같이 스케줄 (논문은 K_d 를 대각 상수로만 씀) |
| 피드포워드 | `τ_ff = JᵀΛ(a_ref − J̇q̇) + Cq̇ + G` (식 2) | `M q̈ + qfrc_bias`, `q̈ = J⁻¹(a_ref [− J̇q̇])` — **수식상 동일** (아래 검산). **`J̇q̇` 는 기본 생략** (`--jdot`) |
| 발 자세 | 없음 (점 발, `J ∈ R³ˣ³`) | **추가**: 발바닥 수평 + 착지 yaw 스프링 `Jrᵀ(k_p axis − k_d ω)` (우리는 6 DOF 다리 + 평발) |
| 스탠스 | `τ = Jᵀ Rᵀ f` (MPC 힘) | `τ = qfrc_bias − (Jpᵀ F + Jrᵀ m)` — **6D wrench** (평발이라 모멘트도) + **중력·코리올리 보상** |
| 접촉 | 조기/늦은 접촉 감지, **조기 접촉이면 즉시 스탠스** | **없음** (어제 `--earlytd` 로 시험 → 튐 때문에 기각, 9/22 Q13) |
| 그 밖 | — | 임피던스 힘 상한 400 N, `‖q̈‖ ≤ 300` 안전 클램프 |

### 2. 피드포워드가 같다는 검산

발 야코비안이 정사각이면 `Λ = (J M⁻¹ Jᵀ)⁻¹ = J⁻ᵀ M J⁻¹` 이므로

```
JᵀΛ(a − J̇q̇) = Jᵀ J⁻ᵀ M J⁻¹ (a − J̇q̇) = M · J⁻¹(a − J̇q̇) = M q̈_des
```

실제 보행 중 세 시점에서 두 식을 계산해 비교: **최대 차이 3e-15 ~ 1e-14 N·m** (토크 크기 5 ~ 7 N·m). 같은 식이다.
우리는 다리 6 DOF 라 `J` 가 6×6 (위치 3 + 자세 3) 이고, 논문은 점 발이라 3×3.

### 3. 남는 차이의 의미

1. **`J̇q̇`** — 논문 식 (2) 에 있고 우리는 기본 생략. 9/21 Q6 에서 켜봤더니 횡 흔들림이 나빠졌는데,
   **그때는 이륙 첫 틱 버그(9/22 Q13)가 있던 상태**다 → 재시험 후보 (Q2 §4 와 같은 항목).
2. **접촉 감지** — 논문은 조기 접촉이면 바로 스탠스로 바꾼다. 우리는 없고, 어제 넣어 본 버전은
   MPC 가 새 접촉을 다음 갱신(≤10 ms)에야 반영해 튐이 생겼다. **MPC 쪽 처리까지 같이 해야 한다**는 뜻.
3. **발 자세·6D wrench** — 평발 휴머노이드라서 우리가 더 붙인 것. 논문에는 없는 축 (CoP·발 yaw 문제도 여기서 나온다).

## Q4. `J̇q̇` 를 이륙 버그 수정 뒤 다시 켜 보면? — 여전히 기각, 그런데 이유가 바뀌었다

### 3. 왜 — 피드포워드가 어디로 가는지 측정 (vx 0.7, 8 ~ 20 s 스윙 틱, 평균 (95 %))

| `M q̈_ff` 의 행 | jdot 끔 | jdot 켬 | |
|---|---|---|---|
| `‖q̈_ff‖` [rad/s²] | 70.8 (183) | 79.7 (166) | +13 % |
| 스윙다리 행 [N·m] — **적용됨** | 14.0 (35.2) | 16.6 (34.3) | +18 % |
| 베이스 **병진** 행 [N] — **버려짐** | **39.3 (99.2)** | **46.7 (95.3)** | +19 % |
| 베이스 **회전** 행 [N·m] — **버려짐** | **16.3 (45.1)** | **19.1 (43.8)** | +17 % |
| 디딤다리 행 [N·m] | **0.0** | **0.0** | — |

1. **디딤다리 행이 정확히 0 이다.** `M` 에 다리↔다리 직접 결합이 없다 (두 다리가 서로 다른 가지) —
   `M[왼다리, 오른다리]` 최대 절댓값 `0.0` 확인. → 코드 주석의 *"M 이 밀집이라 stance 관절에도 보상이 들어간다"* 는 **틀렸다. 정정.**
2. **베이스 행이 크다** — 병진 39.3 N (체중 327 N 의 **12 %**, 95 % 30 %) + 회전 16.3 N·m,
   스윙다리 행 14.0 N·m 보다 큰 요구다. 그런데 `τ = qfrc_bias[adof] + tau_c[adof]`,
   `adof = 6..34` 라 **버려진다.** 플로팅 베이스엔 모터가 없다.
3. 즉 "다리를 이렇게 가속시키겠다" 는 요구의 3/4 는 모터가 아니라 **골반과 접촉이 떠안는다.**
   `J̇q̇` 를 켜면 그 요구가 18 % 커진다 → 골반이 더 들리고 (수직가속 최저 −5.0 → −3.7 = 골반이 덜 내려앉음)
   디딤발이 뜬다 (합력 16 %). **스윙 추종오차가 오히려 나빠진 것도 이 때문** — 실현 발 가속은 어차피 `a_ff` 가 되지 않고, 명령만 커졌다.
4. 하중 여유가 있는 0.3 · 0.5 에서는 합력이 54 → 54, 57 → 55 로 거의 그대로다. **0.6 부터 무너진다** (56 → 26, 54 → 16).

### 4. 결론과 다음

- **`--jdot` 기본 꺼짐 유지.** 단 이유가 바뀌었다 — "횡 흔들림" 이 아니라 **하중 인계** 다.
- 논문(Cheetah 3) 형태 `JᵀΛ(a − J̇q̇)` 로 바꿔 넣어도 이 문제는 그대로다. `Jᵀ` 의 베이스 행도 똑같이 버려진다.
  치타는 다리가 가벼워 그 반작용이 무시할 만했고, **G1 은 다리가 전체 질량의 43 %** 다 (Q3 §3 과 같은 갈래).
- **진짜 해결은 MPC 쪽이다** — 스윙 다리 반작용을 디딤 wrench 계획이 미리 알게 하는 **다리 각운동량 아핀항** (9/22 Q9, 다음 할 일 ①).
  이번 시험이 그 항의 필요성을 수치로 준다: 매 스윙마다 **체중의 12 % (95 % 30 %) 에 달하는 병진 요구 + 16 N·m** 가 계획 밖에서 접촉으로 흘러간다.

## Q5. 그래서 `J̇q̇` 의 역할이 뭔데?

**한 줄 답.** **관절을 전혀 가속시키지 않아도 (`q̈ = 0`) 발에 생기는 가속**이다.
다리가 호를 그리며 휘둘리기 때문에 생기는 **구심가속**이고, 그래서 발 속도의 제곱으로 커진다.

### 1. 식에서의 자리

발 위치 `p = f(q)` 를 두 번 미분하면

```
ṗ = J q̇
p̈ = J q̈  +  J̇ q̇
     └ 관절을 가속시켜 만드는 몫    └ 관절 속도가 그대로여도 생기는 몫
```

두 번째 항은 **속도 제곱 항**이다 (`J̇` 안에 `q̇` 가 또 들어 있다). 팔을 일정한 각속도로 돌리면
손끝은 각가속도가 0 인데도 어깨 쪽으로 `ω²L` 의 구심가속을 받는 것 — 그게 `J̇q̇` 다.

그래서 "발을 `a_ref` 로 가속시켜라" 를 관절 명령으로 바꿀 때는 이미 공짜로 생기는 몫을 빼야 한다:

```
q̈_des = J⁻¹ (a_ref − J̇q̇)        ← 빼면 실현 가속 = a_ref
q̈_des = J⁻¹ a_ref                ← 안 빼면 실현 가속 = a_ref + J̇q̇
```

### 2. 정말 구심가속인지 측정 (vx 0.5, 8 ~ 16 s, 스윙 3436 틱)

| | 값 |
|---|---|
| 발 속도 `|v|` (골반 기준) | 평균 **1.15** m/s, 최대 1.78 |
| `J̇q̇` 중 **v 에 수직** 성분 | **3.33 m/s² (81 %)** ← 구심 |
| `J̇q̇` 중 v 와 나란한 성분 | 0.78 m/s² (19 %) |
| 방향이 **골반 쪽**을 가리키는 정도 (cos) | **+0.86** |
| 등가 회전반경 `|v|²/|a_수직|` | **0.44 m** (엉덩이~발 거리 0.65 m) |

`v²/r = 1.15²/0.44 = 3.0 m/s²` 이고 실측 수직성분이 3.33 — **거의 그대로 진자 구심가속이다.**
스윙 구간별로도 발이 제일 빠른 25 ~ 50 % 에서 가장 크다:

| 스윙 위상 | 0~25 % | 25~50 % | 50~75 % | 75~100 % |
|---|---|---|---|---|
| 발 속도 [m/s] | 1.02 | **1.61** | 1.25 | 0.71 |
| `|J̇q̇|` [m/s²] | 3.34 | **4.41** | 3.99 | 2.34 |
| 골반 방향 cos | +0.76 | +0.89 | +0.91 | +0.89 |

즉 **다리를 휘두르는 내내 발은 골반 쪽으로 3 ~ 4.4 m/s² 씩 끌려간다** (= 다리가 짧아지는 쪽).
빼지 않으면 발은 계획보다 그만큼 더 골반 쪽으로 가속된다.

### 3. `qfrc_bias` 와 헷갈리지 말 것

우리 토크식은 `τ = qfrc_bias + …` 로 **관절공간** 속도항 `C(q,q̇)q̇` 를 이미 전부 보상한다.
그런데 그걸 완전히 보상해도 `M q̈ = JᵀF` 이므로

```
p̈ = J M⁻¹ Jᵀ F + J̇q̇ = Λ⁻¹F + J̇q̇
```

**작업공간 항 `J̇q̇` 는 그대로 남는다.** 둘은 같은 물리(속도 제곱)에서 오지만 좌표계가 달라서,
`qfrc_bias` 를 넣었다고 `J̇q̇` 가 처리되는 게 아니다. 논문 식 (2) 에 `Cq̇ + G` 와 `J̇q̇` 가
**둘 다** 들어 있는 이유가 이것이다 (Q3).

### 4. 그런데 왜 우리는 빼지 않나

빼는 쪽이 식으로는 옳지만, 우리는 그 보상을 `M q̈` 로 흘려보내고 그 요구의 3/4 이
모터 없는 베이스 행으로 버려진다 → 켜면 착지 합력 최저가 54 → 16 % 로 무너진다 (**Q4**).
**"항이 틀렸다" 가 아니라 "넣는 통로가 없다"** 가 맞는 요약이다.

### 5. 앞으로 중요해지는 이유

`|J̇q̇| ≈ v_발²/r` 이라 **속도의 제곱으로 커진다.** 0.5 m/s 에서 발 속도 1.15 m/s → 3.5 m/s² 인데,
목표인 **1 m/s 에서는 발 속도가 2 배 → 이 항이 3 ~ 4 배**가 된다 (`a_ref` 대비 34 % → 그 이상).
그때는 무시할 수 없으니, `M q̈` 통로가 아니라 **MPC 가 스윙 반작용을 미리 아는 형태**로 넣어야 한다
(다리 각운동량 아핀항, 9/22 Q9 · 다음 할 일 ①).

## Q6. "항이 틀린 게 아니라 넣을 통로가 없다" 가 무슨 말인가?

**한 줄 답.** 스윙 피드포워드는 "발을 이렇게 가속시키려면 이런 힘들이 필요하다" 는 **35 줄짜리 요구서**인데,
그중 관절 줄은 모터가 있어 실행되고 **골반(플로팅 베이스) 줄은 모터가 없어 그냥 버려진다.**
그 골반 줄을 실행해 줄 수 있는 유일한 후보는 **땅 딛은 발의 힘 = MPC 가 정하는 wrench** 인데,
우리 MPC 모델엔 스윙 반작용 항이 없어서 그 요구가 존재하는지도 모른다. 그래서 "받아 줄 통로가 없다".

### 1. 요구서를 줄별로 뜯어보면 (vx 0.7, 8 ~ 20 s, 스윙 5155 틱, 평균 (95 %))

`τ_ff = M(q) q̈_ff` 는 `nv = 35` 줄 (베이스 6 + 관절 29) 이다.

| 줄 | 뜻 | jdot 끔 | jdot 켬 | 실행되나 |
|---|---|---|---|---|
| 베이스 병진 3 줄 | "골반을 이만큼 밀어 줘" | **39.3 N** (99.2) = 체중의 **12 %** (95 % 30 %) | 46.7 N (+19 %) | ✗ **모터 없음** |
| 베이스 회전 3 줄 | "골반을 이만큼 비틀어 줘" | **16.3 N·m** (45.1) | 19.1 (+17 %) | ✗ **모터 없음** |
| 스윙다리 6 줄 | "이 관절들을 이렇게 가속시켜" | 14.0 N·m (35.2) | 16.6 (+18 %) | ○ |
| 디딤다리 6 줄 | — | **0.0** | **0.0** | (요구 자체가 0) |
| 상체 | 작음 | — | — | ○ |

코드에서 버려지는 자리는 [09_walk.py:552](../MPC/src/09_walk.py#L552) 한 줄이다:

```python
tau = d.qfrc_bias[self.adof] + tau_c[self.adof]      # adof = 6..34
```

`tau_c` 는 35 줄인데 `[adof]` 로 **0 ~ 5 번 (플로팅 베이스) 을 잘라 낸다.** 잘라 내는 게 버그는 아니다 —
골반에 모터를 달 수 없으니 달리 방법이 없다. 문제는 **잘라 낸 요구가 사라지지 않는다**는 것이다.

### 2. 잘린 요구는 어디로 가나

물리적으로 그 6 줄은 *"다리가 계획대로 가속하는 동안 누군가 골반을 39 N 으로 받쳐 주고 16 N·m 으로 잡아 줘야 한다"* 는 뜻이다.
우주에서 팔을 휘두르면 몸이 반대로 도는 것과 같은 이야기고, G1 은 **다리가 전체 질량의 43 %** 라 그 반작용이 크다.

로봇에서 골반을 받쳐 줄 수 있는 것은 **땅을 딛은 발의 접촉력** 하나뿐이다. 그 힘은 MPC 가 정한다.
그런데 우리 MPC 는 **단일 강체(SRB) 모델** 이라 "다리를 휘두르면 골반에 이런 반작용이 온다" 는 항이 아예 없다
(9/16 Q8 의 `L_다리` 아핀항이 바로 그 자리). 그래서 이 요구는

- 모터가 실행하지도 않고 (베이스엔 모터가 없다),
- MPC 가 계획에 넣지도 않는다 (모델에 그 항이 없다).

결과: 골반이 그냥 밀리고, 남는 것을 **접촉력과 CoP 가 사후에 떠안는다** → 착지 직후 합력이 꺼지고 CoP 명령이 튄다.

### 3. 그래서 `J̇q̇` 를 켰을 때 왜 나빠졌나

`J̇q̇` 를 빼면 **다리 쪽 식은 더 정확해진다** (실현 발 가속 = `a_ff`). 대신 같은 비율로
**아무도 받아 주지 않는 골반 요구가 19 % 커진다** (39 → 47 N, 체중의 12 → 14 %).
그 몫이 접촉으로 흘러가 착지 하중 인계가 무너진다 (합력 최저 54 → 16 %, Q4).
**항이 틀린 게 아니라, 항을 정확하게 만든 만큼의 반작용을 받아 줄 통로가 없다**는 뜻이 이것이다.

논문 형태 `JᵀΛ(a − J̇q̇)` 로 바꿔도 같다 — `Jᵀ` 에도 베이스 행이 있고 똑같이 잘린다.
치타(Cheetah 3)는 다리가 가벼워 이 몫이 무시할 만했다 (Q3 §3).

### 4. 통로를 만드는 방법 (= 다음 할 일 ①)

**MPC 에게 알려 주는 것** 말고는 없다. 다리 각운동량 아핀항 (9/16 Q8, 9/22 Q9):
계획된 스윙 궤적으로부터 `L̇_다리` 를 미리 계산해 SRB 동역학의 상수항으로 넣으면,
MPC 가 **그 반작용을 미리 아는 디딤 wrench 를 계획한다.** 그러면 골반 요구가 "버려지는 줄" 이 아니라
"디딤발이 내야 할 힘" 으로 바뀐다. 그때 `J̇q̇` 도 같이 켜서 재시험하는 것이 맞는 순서다.

참고로 `|J̇q̇|` 는 0.5 m/s 에서 3.5, **0.7 m/s 에서 4.9 m/s²** 로 이미 커지고 있다 (속도 제곱, Q5 §5).

## Q7. "골반에 모터를 달 수 없다" 가 무슨 뜻인가?

**한 줄 답.** 모터는 **두 몸체 사이**에만 달 수 있는데, 골반의 6 자유도는 `world` 와 `pelvis` 사이다.
world 는 밀어낼 실체가 아니다 — **골반을 밀어 줄 상대가 없다.** 걷는 로봇은 접촉 말고는 자기 몸 전체를 움직일 수단이 없다.

### 1. 모델이 말해 주는 것

```
nv (자유도) = 35,  nu (모터) = 29,  차이 = 6
  관절 0: 'floating_base_joint'  형식=free(6)  부모몸체='world' -> 자식='pelvis'
  관절 1: 'left_hip_pitch_joint' 형식=hinge(1) 부모몸체='pelvis' -> 자식='left_hip_pitch_link'
모터가 붙은 dof: 6 ~ 34     모터 없는 dof: [0, 1, 2, 3, 4, 5]
```

- **관절 1번 (엉덩이 피치)**: `pelvis` 와 `left_hip_pitch_link` 사이. 모터가 둘을 서로 밀어낸다 (작용–반작용).
  다리를 앞으로 차면 골반은 뒤로 밀린다 — **둘 다 로봇의 일부라 내부에서 주고받는다.**
- **관절 0번 (플로팅 베이스)**: `world` 와 `pelvis` 사이. 형식이 `free` — 이건 사실 **관절이 아니라**
  "로봇이 공중에 떠 있고, 그 위치 3 + 자세 3 이 상태변수다" 라는 시뮬레이터의 표현이다.
  여기에 모터를 달려면 **땅이나 천장에 고정된 장치(크레인·지그·짐벌)가 골반에 물려 있어야** 한다.
  자유롭게 걷는 로봇에는 그런 게 없다. 그래서 이 6 자유도는 **비구동(underactuated)** 이다.

### 2. 운동방정식으로 보면

```
M q̈ + h = Sᵀ τ + Σ Jcᵀ f        S = [0_(29×6)  I_29]   ← 모터는 관절 줄에만 들어간다
```

윗쪽 **베이스 6 줄** 만 떼어 내면

```
M_base q̈ + h_base = Σ J_c,base ᵀ f        ← τ 가 아예 등장하지 않는다
```

이 6 줄은 사실 **로봇 전체의 뉴턴–오일러**다: `ΣF = m a_com`, `ΣM = L̇`.
외력은 **중력과 접촉력뿐**이다. 사람도 똑같다 — 공중에 뜬 채로 아무리 힘을 줘도 몸 전체를 위로 밀 수 없다.
팔다리를 휘둘러 자세를 바꿀 수는 있어도 무게중심 궤적은 못 바꾼다. **발이 땅에 닿아야 한다.**

### 3. 그래서 우리 구조의 역할 분담이 이렇게 갈린다

| 방정식 | 누가 담당 | 수단 |
|---|---|---|
| 관절 29 줄 | **500 Hz 토크식** ([09_walk.py](../MPC/src/09_walk.py) `torque`) | 모터 토크 |
| **베이스 6 줄** | **100 Hz MPC** ([mpc_srb.py](../MPC/src/mpc_srb.py)) | **접촉 wrench 를 정하는 것** |

MPC 상태 `x ∈ R¹³` 의 12 개(자세 3 + 위치 3 + ω 3 + v 3)가 **정확히 이 모터 없는 6 자유도의 위치와 속도**다.
SRB MPC 가 하는 일이 곧 "모터로 못 건드리는 6 줄을 접촉력으로 어떻게 몰 것인가" 다.

그래서 Q6 의 결론이 나온다 — 스윙 피드포워드가 만들어 낸 **골반 요구(병진 39 N = 체중 12 %, 회전 16 N·m)는
MPC 담당 구역에 쓰인 요구서**인데, 토크식은 그 줄을 실행할 수 없어 잘라 내고 MPC 에는 전달되지 않는다.
전달 통로를 만드는 것이 다리 각운동량 아핀항이다 (다음 할 일 ①).

## Q8. MPC 에 전달하려면 Residual MPC 처럼 `q` 항을 추가해야 하나? 전달할 방법이 있나?

**한 줄 답.** 두 가지 길이 있는데, **비용 가중치 `Q` 는 통로가 아니고**, 상태에 관절 `q` 를 넣는 전신 MPC 는 맞지만 너무 비싸다.
우리에게 맞는 건 **세 번째 — 동역학 제약의 아핀항 `c_k`** 다. QP 크기·풀이 시간이 **전혀 안 늘어난다.**

### 1. 세 후보 비교

| 통로 | 무엇 | 되나 |
|---|---|---|
| **① 비용 가중치 `Q`** | pitch 오차를 더 싫어하게 | ✗ **통로가 아니다.** Q 는 "무엇을 더 싫어할지" 만 정한다. 다가올 외란을 **알려 주지 못한다** — 이미 생긴 오차에 더 세게 반응할 뿐(사후 대응) |
| **② 상태에 관절 `q` 추가** (전신 MPC, Residual MPC 논문 방식) | 다리를 모델 안에 넣어 반작용이 **저절로** 나오게 | ○ 원리적으로 가장 옳다. ✗ 상태 13 → 13 + 관절, 동역학이 비선형이라 QP 가 아니게 된다. 100 Hz 유지가 어렵다 |
| **③ 아핀항 `c_k`** | 계획된 스윙에서 **미리 계산한 반작용**을 동역학의 상수항으로 주입 | ◎ **우리 답.** 다리를 상태로 넣지 않고 그 효과만 넣는다 |

② 가 왜 비싼지: Residual MPC 는 전신 모델 MPC 라 다리가 상태 안에 있고, 그래서 스윙 반작용을
따로 알려 줄 필요가 없다. 대신 그 대가로 비선형 최적제어(iLQR/DDP 류)를 푼다.
우리는 **볼록 QP 로 100 Hz** 라는 구조를 지키는 게 이 논문의 전제다 (Cheetah 3 계열, Q3).

### 2. 아핀항이 들어가는 자리

이산 동역학이 지금은 이렇다:

```
x_{k+1} = A_d x_k + B_d u_k                 (+ 중력은 13번째 상태로)
```

중력은 이미 **아핀 채널**로 들어가 있다 — [mpc_srb.py:161](../MPC/src/mpc_srb.py#L161) 의 `A[11, 12] = -1.0`,
즉 `g = 9.81` 인 13번째 상태 (Di Carlo 트릭). **그런데 이건 상수만 된다.**
스윙 반작용은 지평 스텝마다 달라서 상태 트릭으로는 못 넣는다 → **명시적 `c_k` 벡터**가 필요하다.

```
x_{k+1} = A_d x_k + B_d u_k + c_k
```

**병진 행 (9:12) 은 손댈 필요가 없다.** 우리 상태 `p, v` 가 `d.subtree_com[0]`, `d.subtree_linvel[0]`
= **전신 CoM** 이라 (`get_state`) `m a_com = ΣF + mg` 가 이미 정확하다.

**근사인 곳은 회전 행 (6:9) 이다.** `ω := I_w⁻¹ L_전신` 로 정의했으므로 `I_w ω = L` 은 정확한데,
오일러 방정식을 미분하면

```
L̇ = I_w ω̇ + İ_w ω = Σ (r×F + m)
  → ω̇ = I_w⁻¹ [ Σ(r×F + m) − İ_w ω ]
                              └────────┘  지금 코드에 없는 항
```

다리를 휘두르면 **전신 관성 `I_w` 가 변한다.** 그 `İ_w ω` 가 곧 골반 pitch 흔들림의 원인이고
(σ 3.4 ~ 4°), Q6 에서 잘려 나가던 "골반을 받쳐 달라" 는 요구의 회전 몫이다.
따라서 `c_k` 의 6:9 줄 = `−dt · I_w⁻¹ İ_w ω` (또는 같은 것을 `L̇_다리` 로 계산).

### 3. QP 비용이 안 늘어나는 이유

condensed 형태가 [mpc_qp.py:280](../MPC/src/mpc_qp.py#L280) 에서 이렇다:

```
X = A_qp x0 + B_qp U
g = 2 B_rᵀ ( q ⊙ (A_qp x0 − X_ref) ) − 2 r ⊙ u_ref
```

`c_k` 는 **입력과 무관한 기지량**이라, 자유응답만 한 번 누적해 두면 된다:

```
d_k = Σ_{j<k} A_d^{k-1-j} c_j          (N=16 번의 13×13 곱 — 무시할 비용)
X   = A_qp x0 + d + B_qp U
g   = 2 B_rᵀ ( q ⊙ (A_qp x0 + d − X_ref) ) − 2 r ⊙ u_ref
```

**H(헤시안)도, 마찰·CoP 제약도, 변수 개수도 그대로다.** 바뀌는 건 g 한 줄 (`A_qp @ x0` → `A_qp @ x0 + d`).
QP 풀이 시간 4.0 ms 는 그대로다. **이게 아핀항을 고른 결정적인 이유다.**

### 4. 계산할 수 있나 (= 다음 할 일 ① 의 실제 내용)

지평은 `N=16 × dt 0.05 = 0.8 s` 앞까지인데, 그 구간의 **걸음 스케줄과 스윙 궤적 식을 우리가 이미 안다**
([gait.py](../MPC/src/gait.py)). 각 지평 스텝의 계획된 발 위치·속도를 그대로 계산할 수 있다.
거기서 `L̇_다리` (또는 `İ_w`) 를 얻으려면 다리 질량 분포가 필요한데, 다리를 몇 개 점질량으로 근사하면 된다.

**순서는 오프라인 검증부터** (9/22 에 적어 둔 대로): 계획된 스윙으로 예측한 `L_다리` vs
MuJoCo 실측 `d.subtree_angmom` 을 비교해 예측 정확도를 먼저 본다. 예측이 틀리면 아핀항은 외란을 **추가**할 뿐이다.

### 5. 솔직한 한계

지금 우리는 **축별 혼합 상태**를 쓴다 — yaw 골반 100 %, roll 골반 50 %, pitch 전신 (9/22 Q2).
아핀항이 위 유도대로 **깨끗하게 정의되는 건 전신 `ω` 축뿐**이다. 다행히 문제가 되는 축이 **pitch 이고 그건 전신**이다.
yaw·roll 은 근사로 남고, 잘못 넣으면 오히려 해가 되니 **pitch 행부터 넣고 A/B** 하는 게 맞다.

그리고 **residual RL 은 여기의 답이 아니다.** 잔차는 *모르는 것*을 메우는 방법인데, 이건 계획에서 **계산할 수 있는 양**이다.
계산 가능한 것을 학습으로 메우면 재현성도 떨어지고 "1 m/s 까지는 MPC 단독" 원칙에도 어긋난다. 아핀항이 먼저다.

## Q9. reference 는 이 문제를 어떻게 처리했나?

**한 줄 답. 처리하지 않았다.** reference 코드 전체에 다리 반작용을 다루는 항이 **없다**
(`momentum` · `disturbance` · `affine` · `residual` grep 0 건, WBC/WBIC 파일 없음).
MPC 상태도 우리와 같은 13 개고, 아핀 채널은 **중력 하나뿐**이다
(`MPCFormulation.cpp:75` `A_c_k.block<3,1>(9,12) << 0,0,1` — 우리 `A[11,12] = −1.0` 과 같은 트릭).
대신 **반작용이 문제가 되지 않게 구조를 짜 놨다.**

### 1. 반작용을 "다룰 필요 없게" 만든 세 가지

| # | 무엇 | 어디 |
|---|---|---|
| ① | **SRB = 상체만.** 다리를 질량·관성에서 아예 제외하고, 상태도 Θ·ω 둘 다 torso → **모델과 상태가 같은 강체** | `setupRobotParams.cpp` (분석 §2) |
| ② | **스윙을 다리 국소 문제로 못박음.** 스윙 토크에 넘기는 `J`, `J̇`, `M`, `bias` 가 전부 **다리 dof 만 잘라낸 것** | `LegSwingDynamicsProvider.cpp` `readDenseMassSubmatrix(indices=다리 dof)`, `copySelectedJacobianColumns`, `copySelectedBias` |
| ③ | **반작용을 작고 예측 가능하게.** 스윙 대역폭 ω_n **100 rad/s**, 다리 bias 정확 보상, 발 자세 3축 PD 상시, ContactManager (실측 접촉력 기반 조기접촉·하중 램프·지면탐색) | `config/unitree_robots/g1/my_controller.yaml`, `ContactManager` |

②가 중요하다 — 그들은 베이스 행을 **버리는 게 아니라 애초에 계산하지 않는다.**
"다리를 휘두르면 골반이 받는다" 를 **모델에 넣지 않기로 정한** 설계다.

### 2. 결정적인 관찰: 우리 식과 그들 식의 **적용 토크는 같다**

우리는 `M_full q̈_ff` 를 만들어 `[adof]` 로 자른다. 자르고 남는 것을 Q6 에서 측정해 보니

- 베이스 6 줄 → 잘린다
- **디딤다리 · 팔 줄 → 정확히 0** (가지가 달라 `M` 결합이 없다)
- 남는 것은 **다리 블록뿐** = `M_다리 q̈_다리`

그리고 `M_다리 q̈ = JᵀΛ_다리(a − J̇q̇)` 임을 이미 검산했다 (9/23 Q3, 차이 1e-14).
**즉 우리가 실제로 내보내는 스윙 토크는 reference 의 식과 같은 것이다.**
그러니 *"그들은 `J̇q̇` 를 켜고도 잘 되는데 우리는 안 됐다"* 의 원인은 **식이 아니다.**

### 3. 그럼 무엇이 다른가 — G1 설정 파일이 그대로 있다

reference 에는 `config/unitree_robots/g1/my_controller.yaml` 이 있어 **같은 로봇**으로 비교된다:

| | reference (G1) | 우리 |
|---|---|---|
| 스윙 대역폭 ω_n | **100 rad/s** (MIT 휴머노이드는 151/151/110) | **30** |
| 스윙 kd | **고정 [20, 20, 23]** | `2ζω_nΛ` (ζ 0.7) |
| → 실효 감쇠비 ζ | `kd/(2ω_nΛ)` = **0.01 ~ 0.08** (거의 무감쇠) | **0.7** |
| 스윙 높이 | 0.09 m | 0.05 m |
| 걸음 주기 / 스윙 / 스탠스 | 0.7 / 0.3 / 0.4 (stance 0.571) | stance 0.57 — **같다** |
| MPC 지평 | 0.5 s, 25 스텝 (dt **0.02**) | 0.8 s, 16 스텝 (dt **0.05**) |
| 입력 가중 R | **1e-7** | 1e-5 |
| 접촉 관리 | **ContactManager** (조기접촉·하중 램프) | 없음 (`--earlytd` 시험 후 기각, 9/22 Q13) |

**ζ 0.01 ~ 0.08 이 핵심이다.** 그들의 스윙 루프는 아주 센 스프링 + 거의 없는 감쇠 + **정확한 피드포워드**로
굴러간다 — 그 구성에서는 `J̇q̇` 의 정확성이 **결정적**이고, 빼면 그들이 손해를 본다.
우리는 ζ 0.7 · ω_n 30 이라 **피드백이 일을 많이 한다** → 피드포워드가 정확해져서 얻는 이득은 작은데,
반작용 비용(Q6 의 골반 요구 +19 %)은 똑같이 낸다. **같은 항이 그들에겐 남고 우리에겐 손해인 이유가 이것이다.**

그리고 우리 `J̇q̇` 손해가 **하중 인계**(합력 최저 54 → 16 %)에서 터졌는데, 정확히 그 지점을
reference 는 **ContactManager 로 관리**한다. 우리에겐 그게 없다.

### 4. 그래서 순서에 대한 판단

Q8 의 **아핀항은 reference 에 없는 우리 독자 경로**다. reference 가 "모델·상태 정합 + 대역폭"으로
**우회한** 문제를, 우리는 "모델에 알려 주기" 로 **정면으로** 풀려는 것이다. 더 원리적이지만 예측 정확도 검증이 선행 조건이다.

한편 reference 는 **더 싼 길**도 보여 준다 — 같은 G1 에서 **ω_n 100 · ContactManager** 로 버틴다.
`J̇q̇` 가 하중 인계에서 무너졌다는 측정을 보면, 다음 할 일 **⑦ 하중 인계**와 **⑥ 게인(ω_n)** 을
아핀항보다 먼저 손대는 것도 타당하다. 셋 다 결국 같은 곳(스윙 반작용)을 향한다.
