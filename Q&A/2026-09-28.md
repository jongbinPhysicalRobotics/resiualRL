# 2026-09-28 (월)

## Q1. 최신 조합은 몇 m/s 까지 가나 + 발뒤꿈치가 몸 바깥으로 도는 현상 — 뿌리는 같다 (MPC 발목 모멘트 포화 → 한 점 접촉)

**결론**
- **속도** (측정, 120 s): `fix=slide+yawref, rai=0.2, ypath=0.3` 는 **0.65 m/s 까지 완주** (추종 94 %).
  0.675 는 45 s, 0.7 이상은 6 ~ 12 s 에 전도.
- **뒤꿈치 현상** (측정): 착지 방향 오차는 작다 (+1.2°). 발이 **땅에 붙은 채** 입각 중에 **앞꿈치를 축으로 돌아**
  뒤꿈치가 바깥으로 6 ~ 7° 나간다 (0.65 m/s, 0.3 m/s 에선 1.5°).
  표의 `slip` (입각 중 발 중심 이동) 8.7 mm 가 바로 이것이다 (75 mm × tan 6.6° = 8.7 mm).
- **기전**: MPC 가 입각의 절반 이상 (0.3 m/s 55 %, 0.65 m/s 63 %, line 81 %) 동안 발목 모멘트 My 를 CoP 한계 (±0.065 m) 까지 쓴다 (측정).
  그래서 실제 발은 절반 가까이 **앞꿈치나 뒤꿈치 한 점**으로 서 있다 (측정).
  그 순간에도 reference 의 비틀림 제약 `|Mz| ≤ 0.0657 µ Fz` 는 CoP 와 무관해 yaw 모멘트 (p95 7 ~ 9 N·m) 를 허용한다 (코드 사실).
  한 점 접촉은 비틀림을 못 버티므로 (condim 3) 발이 앞꿈치를 축으로 돈다 (추론, 위상 프로파일로 뒷받침).
- **속도 벽과의 관계**: 0.675 전도는 발이 뒤꿈치 쪽으로 −10 ~ −12° 구르면서 시작한다 (평소 −2 ~ −4°, 측정).
  발목 모멘트 포화라는 같은 뿌리가 yaw 로는 뒤꿈치 회전, pitch 로는 발 구름으로 나타난다 (추론).
- **발목을 왜 그렇게 쓰나**: MIT reference 의 SRB 는 몸통 + 팔 (14.23 kg) 뿐이고 **다리 10.66 kg (43 %) 이 모델에 없다** (코드 사실).
  MPC My 가 다리 y 각운동량 변화율과 상관 +0.76 (지연 28 ms), 크기도 비슷하다 (13 vs 16.5 N·m, 측정).
  → 스윙 다리의 반동을 발목으로 막고 있다 (추론).
- **시도한 고침**: `foot=line` (OA-MPC 선 접촉 비틀림 결합) 이 뒤꿈치 회전을 7 → 2.4° 로 줄이고 0.5 ~ 0.65 · 옆걸음을 완주한다.
  그러나 **제자리 회전 1.3 rad/s 에서 2.9 s 전도** → 그대로 채택할 수 없다.
  팔 흔들기·CoP 축소·비용 조정은 뒤꿈치는 고치거나 못 고치거나, 어느 쪽이든 넘어진다. **속도 벽을 넘긴 변형은 없다.**
  다음 후보 = **다리 운동량 아핀항** (G1 affine 폴더 방식을 이식, §6).

### 3. 수직축 · pitch 각운동량 수지 (0.65 m/s, 전신 CoM 기준, 측정)

- 다리 Lz 는 한 주기에 ±0.3 N·m·s 로 흔들린다 (std 0.21).
  **팔은 명령 없이도 반대 위상으로 −0.1 흔들린다** (std 0.08). 팔 PD (kp 100) 가 물러서 생기는 수동 흔들림이다.
  이는 CAM 논문 (Lee·Jeon·Kim RA-L 2025, 이 URDF 의 출처) 이 보고한 "팔과 다리가 반대 위상으로 상쇄" 와 같은 모양이다
  ([ARM_SWING_PLAN.md](../MPC/ARM_SWING_PLAN.md) §1).
- pitch: MPC My (두 발 합) 와 다리 Ly 변화율의 상관은 **+0.76** (지연 28 ms ≈ MPC 두 주기). std 13.1 vs 16.5 N·m.
  → MPC 발목 모멘트의 대부분이 스윙 다리 반동을 막는 데 쓰인다 (상관 = 측정, 인과 = 추론).
- yaw: MPC Mz 와 다리 Lz 변화율의 상관은 −0.35 로 약하다.
  발이 몸 옆 ±w 에 있어 전진·제동력 Fx 가 만드는 yaw 모멘트 (−w·Fx) 가 섞이기 때문으로 본다 (추론).

> 남은 방향: (a) 접촉 제약을 물리에 맞추기 — `line`.
>   걷기 stance yaw hold 가 MPC 밖에서 Mz 를 더해 결합 비틀림 제약을 우회한다 (코드 사실, [leg_control.py](../MPC/src/casadi_mit/leg_control.py) `walking_stance_torque`).

## Q2. 0.675 전도는 k_half 두 번째 전환 (0.65 초과 → 0.26) 탓인가 — 절반은 그렇다

**결론** (측정, 120 s, `fix=slide+yawref, rai=0.2, ypath=0.3` 공통):
- 오늘 벽 (0.65 ✓ / 0.675 ✗) 은 k_half 두 번째 전환선 (strict `>` 0.65 → 0.26, [planner.py](../MPC/src/casadi_mit/planner.py) `selected_half_stance_offset`) 과 겹친다.
- **0.28 로 고정하면 0.675 가 완주**한다 → 0.675 전도는 전환 탓이 맞다.
- 그러나 **실제로 낸 속도의 천장은 거의 그대로**다. 0.28 고정: 0.7 명령은 39 s 전도 (실측 0.67).
  0.37 고정: 0.7 명령이 완주하지만 실측 0.61 m/s 로 **브레이크 걸린 채** 걷는다 (9/26 Q1 의 저속 모양과 같다).

| k_half | 0.675 명령 | 0.7 명령 |
|---|---|---|
| 속도 전환 (reference, Q1) | ✗ 45.4 s (실측 0.66) | ✗ 11.2 s (0.73) |
| 0.28 고정 | **✓ 120 s, 추종 95 % (0.64)** | ✗ 39.4 s, 96 % (0.67), fallback 14 |
| 0.37 고정 | ✓ 120 s, 88 % (0.59) | **✓ 120 s, 87 % (0.61)** |

읽기 (추론):
- k_half 는 "발을 얼마나 앞에 디디나" = 브레이크 세기다. 크면 안정하지만 느리고, 작으면 빠르지만 넘어진다.
- 지금 구성에서 **안정하게 낸 실측 최고 속도는 0.64 m/s** (0.675 명령, k_half 0.28) 다.
- 전환을 없애면 벽이 명령 축에선 뒤로 밀리지만, 실측 속도 축에선 0.6 대 중반에 머문다.
  발목 포화 (Q1) 라는 한계는 그대로라는 뜻으로 읽는다.

## Q3. 발산할 때 OSQP 가 수렴하지 못하는 이유 — 해는 있다, 200 회 cold start 로 못 풀 뿐 (정확히 풀면 안 넘어지지만 느리다)

**결론** (측정, 0.6 ~ 0.7 m/s, `fix=slide+yawref, rai=0.2, ypath=0.3`)
1. **풀 수 없는 문제가 아니다.**
   - 실패한 QP (0.7: 11 개, 0.675: 18 개) 를 quadprog 로 풀면 전부 풀린다 (제약 위반 1e-12).
   - OSQP 도 반복 350 ~ 625 회면 수렴한다.
2. **거의 매번 cold start.**
   - `slide` 는 접촉표가 매 풀이 바뀌고, 코드는 접촉 패턴이 바뀌면 OSQP 를 다시 만들고 warm start 를 버린다
     ([mpc.py](../MPC/src/casadi_mit/mpc.py) `_solve_osqp`, reference 동작 — 코드 사실).
   - 걷기 풀이의 92 ~ 97 % 가 cold 다. warm 은 중앙 25 회에 전부 수렴, cold 는 중앙 175 ~ 200 회이고 36 ~ 60 % 가 200 회 한도에 걸린다.
   - `slide` 없이는 89 % 가 warm, 중앙 50 회.
3. **문제가 나쁜 조건이다.**
   - P 고유값 0.002 ~ 12 000 (조건수 6e6). **고유값의 절반 (150 / 300) 이 정확히 0.002 = 2 × 입력 가중치**다.
   - 몸 동역학은 두 발 합력·합모멘트 (6) 만 보므로, 스텝마다 "두 발 사이로 옮기는" 6 방향이 입력 가중치 1e-3 로만 정해진다.
   - 여기에 상태 가중치 최대 1e6 (py) 이 겹친다.
4. **종료 판정이 느슨하다.**
   - eps 1e-3 × ‖q‖∞ (≈ 3.8e3) ≈ 3.8 인 쌍대 잔차면 "solved" 다.
   - 곡률 0.002 방향에선 수백 N 차이도 통과한다 (추론).
   - 실제로 "solved" 해의 첫 스텝이 정확해와 **합력 110 ~ 120 N, 모멘트 8 ~ 10 N·m** 다르다 (한 발 · 두 발 지지 모두, 목적함수 차 5e-4).
   - OSQP 를 1e-8 까지 조이면 quadprog 와 0.01 N 안에서 같다 → 정확해 계산은 맞다.
5. **재시도가 헛돈다.**
   - 첫 시도가 이미 cold 면 재시도 (새로 만들고 warm 없이) 는 같은 계산이라 매번 같게 실패한다 (측정: 실패 쌍 전부 동일).
   - 그러면 fallback wrench (수직력 mg / 발 수, 수평력 · 모멘트 0, [mpc.py](../MPC/src/casadi_mit/mpc.py) `fallback_wrench`) 가 들어간다.
   - 0.675 에선 fallback 연속이 44.52 s 에 시작, 발 구름 (< −6°) 이 44.78 s, 전도 46.35 s (순서 = 측정, 인과 = 추론).
   - 25.8 · 41.8 s 의 단발 실패는 버텼다.
6. **정확하게 풀면** (quadprog, 또는 OSQP 4000 회 · eps 1e-5) **0.65 ~ 0.7 모두 120 s 완주 — 그러나 실측 0.41 ~ 0.44 m/s (추종 62 ~ 64 %).**
   - roll σ 0.006 → 0.004, pitch σ 0.056 → 0.039 로 오히려 안정.
   - 원인 분리 (0.6 m/s, 30 s, quadprog):

     | fix | 추종 |
     |---|---|
     | yawref (주기 원점 표) | **88 %** |
     | slide + yawref | 57 % |
     | + rai 0.2 | 62 % |
     | + ypath 0.3 | 56 % |
     | + rai + ypath | 61 % |
     | 같은 구성 OSQP 기본 | 90 % |

   → **정확해가 느려지는 건 `slide` 때문이다.**
   - 가설 (추론, 미확인): 지평 (0.5 s) = 한 주기라 `slide` 에선 지평 끝에 디딤 발의 **다음 입각이 항상 들어간다.**

   - OSQP 200 회는 지평 후반을 덜 풀어서 (부정확) 오히려 빨리 걸었다.
   - 즉 9/27 Q3 의 `slide` 채택 근거 (하중 대칭) 는 OSQP 부정확 해 위에서 측정한 것이다.

## Q4. Residual MPC 논문은 풀이기를 어떻게 다루나 — 수렴을 기다리지 않는다 (고정 25 회), 대신 잘 풀리는 문제를 만든다

출처: Jeon et al., *Residual MPC*, IEEE T-RO 42, 2026 (저장소 루트 `ResidualMPC.pdf`, III-A ~ D 절 · V-A 절 · 부록 A). 이 항목은 문헌 사실이다.

| 항목 | 논문 | 우리 (casadi_mit) |
|---|---|---|
| 모델 | **floating-base kinodynamic** (기저 운동방정식 M_b q̈ + h_b = J_bᵀF, 전신 q · q̇ · F 가 변수) — SRB 아님 | SRB (13 상태 · 12 입력) |
| 비선형 처리 | SQP **real-time iteration: MPC 한 번에 QP 1 개** | 선형 · QP 1 개 |
| QP 형태 | 희소 (모든 스텝 상태가 변수, 동역학은 등식), 지평 T = 12 | **condensed** (입력만 변수), 25 스텝 |
| 풀이기 | OSQP 방식 ADMM. KKT 를 풀이당 **한 번만** LDLᵀ 분해 (σ · ρ 고정이면 KKT 불변), 반복은 역대입만 | OSQP, adaptive ρ (50 회마다 재분해) |
| 반복 수 | **고정 N_QP = 25** ("고정 횟수 또는 수렴까지"). 수렴 판정에 기대지 않는다 | 200 회 한도 + eps 1e-3 판정, 실패 시 재시도 → fallback |
| 반복 수 근거 (Fig. 4) | 생존율: 6 회 이하 0 %, 7 ~ 8 회 약 50 %, 10 회 약 90 %, **12 ~ 15 회부터 97 ~ 98 % 포화** (영 명령 + 초기 속도 교란 ±0.5 m/s · ±0.5 rad/s). 여유를 두어 25 | — |
| 초기 추정 | 현재 상태 · 명령으로 **공칭 자세를 지평에 반복, 나머지 0** (이전 해 warm start 가 아니다) | 이전 해 이동 (warm), 접촉 바뀌면 0 |
| 스케일링 | Ruiz 평형화 (KKT 조건 개선) | OSQP 내장 scaling 10 회 |
| 참조 | 원하는 **수직력 = 체중 / 접촉 수** 를 비용에 둔다. **x · y 위치 가중치 0** (절대 위치 드리프트에 둔감하게) | 힘 참조 없음 (입력 가중 1e-3), 위치 가중 2e5 · 1e6 |
| 접촉표 | 고정 주기 0.8 s, 위상 0.5 교대 (두 발 지지 없음), 평발 | 주기 0.5 s, 스윙 0.17 s (두 발 지지 32 %) |
| 계산 시간 | 로봇: **MPC 100 Hz, OSQP, CPU 단일 스레드 200 ~ 300 Hz 가능**. 학습 (GPU 1000 환경): 한 스텝 504.6 ms 중 ADMM 반복 70.7 %, KKT 분해 16.5 % | 풀이 중앙 18 ms (slide 44 ms), Python |
| 발산 대책 | fallback 없음. MPC 해가 발산하는 경우를 인정하고, 잔차 정책 합성을 joint–torque 로 골라 부적절한 q_MPC 설정점을 피한다 (IV-B 절). 잔차 정책이 안정화 | fallback wrench |

우리에게 주는 뜻 (추론):
- 그들이 25 회로 충분한 것은 **문제가 잘 풀리는 모양**이기 때문으로 보인다.
  - 희소 형식 + Ruiz 평형화.
  - **힘 참조 (체중 / 접촉 수)** 가 두 발 분배의 평평한 방향에 곡률을 준다 → 우리 Q3 의 150 개 0.002 고유값에 해당하는 문제가 없다.
  - x · y 위치 가중치 0 → 1e6 급 가중치가 없다.
- "real-time iteration" 관점에선 해가 부정확해도 100 Hz 로 자주 풀면 폐루프는 안정할 수 있다.
  우리 OSQP 200 회 해가 정확해보다 빨리 걸은 것 (Q3 §6) 도 같은 맥락이다.
  단, 그것은 **정확한 최적해가 좋은 걸음이 아니라는 신호** (slide 지평의 발 위치 문제) 이기도 하다.
- 모델 확장 없이 풀이 성질만 바꾸는 후보 (SRB 유지, 사용자 방침과 맞다):
  - (a) 힘 참조 · 두 발 분배 정칙화
  - (b) 위치 가중치 재조정
  - (c) 접촉이 바뀌어도 warm start 유지
  - (d) 희소 형식 (재작업 2 단계 계획)
  - (e) 고정 반복 + 실패 시 fallback 대신 마지막 반복 해 사용

## Q5. 논문식 고정 반복 ADMM 으로 몇 회가 필요한가 — ρ 가 결정적, 그리고 정확해는 제자리 회전에서 넘어진다

**결론**
- (측정) OSQP 기본 ρ 0.1 은 이 문제 크기와 맞지 않다.
  - ρ 0.1 고정이면 반복을 400 회로 늘려도 첫 스텝 힘 오차가 143 → 133 N 이다.
  - 고정 반복 25 · 200 회 모두 걷기 전 서기에서 바로 넘어진다.
  - **ρ 1e-5** 면 200 회에 1.8 N 까지 수렴하고, 제약 위반도 25 회 1.1 N · 200 회 0.01 N 로 작다.
- (측정) 그러나 ρ 1e-5 고정 반복으로는 **세 목표를 모두 넘는 N 이 없다.** 반복 수와 결과가 단조롭지도 않다.
- (측정) **정확해 (quadprog, slide 없음) 도 제자리 회전 1.3 rad/s 에서 7.2 s 에 넘어진다.**

## Q6. 정확해가 제자리 회전에서 넘어지는 원인 = 착지 yaw 선행 — 끄면 모든 풀이기가 완주, warm 고정 반복은 15 회부터 세 목표 통과

**결론** (측정, 120 s, `fix=yawref, rai=0.2, ypath=0.3` 공통, slide 없음)
- 원인 후보 7 개를 정확해 (quadprog) 로 15 s 씩 켜고 꺼 봤다. **착지 yaw 선행 (`swing_foot_yaw_lead_scale`) 을 끄면 (`yawlead=0`) 만 통과**했다.
  - 마찰 원뿔 불일치 가설은 틀렸다.
    - MPC 는 사각 피라미드로 모서리에서 √2 µ 를 허용하고, MuJoCo 기본 pyramidal 은 마름모 |f₁| + |f₂| ≤ µf_n 이다 (코드 사실). 불일치 자체는 사실이다.
    - 그러나 MPC µ 0.5 · 0.7, 시뮬 elliptic 모두 넘어졌다.
- 선행을 끄면 제자리 회전 1.3 rad/s 가 **정확해 · 기존 OSQP · 기존 + ρ 1e-5 · 고정 반복 (warm 15 회 이상, 공칭 25 회 이상) 모두 120 s 완주, 추종 100 %.**
- 선행은 ψ̇ 에 비례해 직진 · 옆걸음엔 0 이다 (코드 사실). 그래서 Q5 의 직진 · 옆 결과는 그대로 유효하다.
- **warm start 고정 반복 ADMM (ρ 1e-5) 은 N = 15 에서 처음으로 세 목표를 모두 넘는다** (N = 5 전도, N = 10 회전 실패).
  논문 Fig. 4 의 포화점 (12 ~ 15 회) 과 비슷하다.

### 1. 착지 yaw 선행이란 (코드 사실, reference 그대로)

착지 yaw = 이륙 순간 몸통 yaw + `lead_scale · ψ̇ · Tp` (Tp = 0.287 s) + 앞장서는 발 `min(100°·|ψ̇|, 20°)`
([planner.py](../MPC/src/casadi_mit/planner.py) `swing_foot_yaw_target_world`, `swing_foot_yaw_psi_offset`).
1.3 rad/s 에선 선행 21° + 20° = **앞장서는 발이 몸통보다 41° 앞**을 보고 착지하도록 계획된다.

### 2. 원인 후보 (정확해, 제자리 회전 1.3, 15 s)

| 변형 | 결과 |
|---|---|
| 기준 | ✗ 7.2 s |
| MPC µ 0.5 / 0.7 | ✗ 6.1 / 9.8 s |
| 시뮬 마찰 원뿔 elliptic / + MPC µ 0.7 | ✗ 5.1 / 4.8 s |
| 디딤 발 yaw hold 끔 (`yawhold=0`) | ✗ 9.2 s |
| **착지 yaw 선행 끔 (`yawlead=0`)** | **✓ 15 s, 추종 100 %** |

## Q7. ⚠ 정정 — 착지 yaw 선행은 스윙 발 회전량을 바꾸지 않는다 · 선행 배율의 의미

- Q6 가설 "선행 때문에 스윙 발이 0.17 s 에 최대 57° 돌아야 한다" 는 **틀렸다** (계산).
  한 다리의 착지 yaw 는 매 주기 같은 선행이 더해지므로, 이륙 → 착지 사이 발 회전량은 선행과 무관하게 ψ̇ · 주기 = 1.3 × 0.5 = 0.65 rad (37°) 다.
- 선행이 바꾸는 것은 **입각 중 발–몸통 yaw 차의 중심**이다. 1.3 rad/s, 앞장서지 않는 발, 스윙 0.17 · 입각 0.33 s 기준 (계산):

  | 선행 배율 | 착지 시 발 − 몸통 | 이륙 시 |
  |---|---|---|
  | 1.0 (reference) | +9° | −16° |
  | 0.5 | −2° | −27° |
  | 0 | −13° | −37° |

  앞장서는 발은 여기에 +20° (`swing_foot_yaw_psi_offset`). 고관절 yaw 한계 ±1 rad (57°).
- 선행이 정확해를 넘어뜨리는 기전은 **미확인**이다. Q6 의 측정 (선행 켬: 입각 중 발 yaw 흩어짐 ±8 ~ 13°, \|Mz\| p95 23 ~ 33 N·m) 은 유효하다.
- 다음: 렌더로 선행 0 의 발 모양 확인 → 필요하면 배율 0.25 / 0.5 / 0.75 를 정확해 · 고정 반복으로 시험.
