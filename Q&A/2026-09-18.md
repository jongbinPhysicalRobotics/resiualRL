## Q1. `--swingid` 는 무엇인가

**스윙 다리를 흔들 때 몸통이 받는 반작용을 미리 갚아두는 항**이다.

### 계산 순서 ([09_walk.py:361-374](../MPC/src/09_walk.py#L361-L374))

```python
a_ff = target_acc(s, p_land, T_swing)   # ① 계획된 발끝 가속도 (스윙 궤적에서 나옴)
qdd  = lstsq(J6, [a_ff, 0])             # ② 발끝 가속 → 관절 가속 (가속 수준 역기구학)
if |qdd| > 300: 클램프                   # ③ 특이자세 보호
qacc[다리 dofs] = qdd
tau_c += M_full @ qacc                  # ④ ★ 전신 질량행렬을 곱한다
```

### ★ 핵심은 ④ 의 `M_full`

`qacc` 는 스윙 다리 6 dof 에만 값이 있는데 **질량행렬 M 은 밀집(dense)** 이라
`M_full @ qacc` 는 **stance 다리와 골반 행에도 값을 만든다.** 그게 물리적으로 정확히
**반작용**이다 — 다리를 앞으로 휘두르면 골반은 뒤로 돌려 하고 그 힘이 stance 다리로 간다.

> 사람으로 치면: 서서 다리를 차려 할 때 **차고 나서 수습**하는 게 아니라
> **차기 직전에 미리 몸에 힘을 주는 것**.

### 왜 필요했나

SRB 는 **다리가 가볍다**고 가정한다. Di Carlo 가 "SRB 가 합리적"이라 한 게 다리 질량
~10 % 일 때인데 **G1 은 43 %** 다. 그러면 스윙 반작용이 **모델에 없는 외란**이 되고
MPC 가 명령한 wrench 와 실현되는 wrench 가 어긋난다.

`--swingid` 는 그 누수를 막아 `τ = qfrc_bias − JᵀW` 의 정확성을 지킨다.
**0.2 m/s 벽을 0.3 으로 민 열쇠**였다 (MPC_NOTES 17절). 격리 실험으로
"스윙 반작용이 원인"을 확정한 뒤 넣은 것이라 추측이 아니라 진단 기반 처방이었다.

### 전체 토크식에서의 위치

```
τ = qfrc_bias              중력·코리올리 보상
  − Σ_stance Jᵀ W          MPC wrench (본체)
  + Σ_swing  Jᵀ F_임피던스  스윙 발 위치 제어
  + M q̈_swing              ← --swingid (반작용 선지급)
```

## Q2. 이 수식들은 어디서 나왔고, 왜 근사했나

### ① `q̈ = J⁺(a_ff − J̇q̇)` — 연쇄법칙을 두 번 쓴 것

```
p = f(q)              순기구학 (관절각 → 발끝 위치)
ṗ = J q̇               ← 양변 미분. 이게 자코비안 J 의 정의 그 자체
p̈ = J q̈ + J̇ q̇        ← 한 번 더 미분 (곱의 미분법)
```

발끝을 `a_ff` 로 가속시키고 싶으면 `a_ff = J q̈ + J̇ q̇` 이므로 `q̈` 에 대해 풀면 끝.

**`J̇q̇` 의 물리적 의미**: **관절이 가속하지 않아도 발끝은 가속한다**는 항.
팔을 **일정한 각속도**로 돌려도 손끝은 중심 쪽으로 가속한다(구심가속도). 그게 이것이다.
크기가 **`q̇²` 에 비례**해서 빠르게 흔들수록 커진다.

### ② `τ = M q̈ + h − JᵀF` — 부유기저 운동방정식

```
M(q) q̈ + h(q,q̇) = Sᵀτ + Jᵀ F
 ↑질량행렬  ↑코리올리+원심+중력  ↑구동  ↑접촉력
```

`h` 가 MuJoCo 의 `qfrc_bias`. τ 에 대해 풀면 `Sᵀτ = M q̈ + h − JᵀF` 이고
우리 코드와 정확히 대응된다:

```
τ = qfrc_bias  −  JᵀW  +  M q̈_swing
     ↑h           ↑JᵀF     ↑ --swingid
```

> **즉 `--swingid` 가 없으면 `q̈ = 0`(준정적)을 가정하는 것이다.**
> swingid 는 버려졌던 `M q̈` 항을 **스윙 다리에 대해서만** 되살린다.

### ★★ 근사가 작지 않다 — 측정 결과 (새 발견)

0.5 m/s 보행 17초, 스윙 구간에서 두 항의 크기를 직접 비교 (J̇ 는 수치미분):

| | 평균 | 최대 |
|---|---|---|
| `‖a_ff‖` (계획 가속) | 10.73 m/s² | 23.47 |
| **`‖J̇q̇‖` (무시한 항)** | **5.86 m/s²** | 16.97 |

**비율 `‖J̇q̇‖/‖a_ff‖` = 평균 69 %, 중앙값 61 %, 상위 10 % 에서 150 %.**
**무시한 항이 본 항보다 클 때도 있다.**

그리고 **`mj_jacDot` 이 MuJoCo 3.12 에 존재한다** (확인함).
API 가 없어서 못 넣은 게 아니라 **작을 거라 보고 생략했는데 그 가정이 틀렸다.**
코드 주석의 "J̇q̇ 항은 생략(근사)" 은 크기를 재본 적이 없었다.

> **미검증 개선 후보**: 스윙 착지오차 4.5 cm 의 일부를 설명할 가능성.
> 피드포워드가 69 % 어긋나면 나머지를 임피던스가 뒤늦게 메워야 한다.
> ⚠ 단, 이 프로젝트에서 "모델 오차를 고쳤더니 나빠진" 전례가 여럿이다
> (제약 frame, LIP-exact, td_mode). **가설이지 확정이 아니다.**

### ⚠ 2026-09-21 후속 측정 — **실제 영향은 위에서 기대한 것보다 작다**

위 "착지오차 4.5 cm 를 설명할 가능성" 은 **과대평가였다.** 두 가지를 재보니:

**① 스윙 추종오차는 97 % 가 xy 다** (9/21 로그, 축별 분해):

| 축 | 평균 | 최대 |
|---|---|---|
| x | 0.81 cm | 3.07 |
| y | **1.21 cm** | **4.74** |
| **z** | **0.21 cm** | 0.71 |

`J̇q̇` 오차는 세 축에 고루 작용할 텐데 **z 는 거의 안 틀린다**.
오차의 주범은 **착지 목표가 스윙 중에 쓸리는 것**(9/16 §4, 14 cm)이지 피드포워드가 아니다.

**② `J̇q̇` 를 보상해도 토크가 크게 안 준다** (0.5 m/s, 스윙 7244 샘플):

| | 현재 (J̇q̇ 무시) | 보상판 |
|---|---|---|
| ‖q̈‖ 평균 | 68.5 | 79.0 |
| ‖q̈‖ 최대 | 266.7 | **219.6** |
| 300 클램프 발동 | **0.00 %** | — |
| `M q̈` 토크 이용률 **최대** | 0.68 | **0.50** |

- 두 `q̈` 는 평균 **43 % 다르다** — 식이 틀린 건 맞다
- **첨두는 줄어든다** (‖q̈‖ 267→220, 토크 이용률 0.68→0.50)
- **그런데 `M q̈` 는 애초에 한계의 0.68 배까지만 쓴다.** 9/18 Q2 에서 잰
  **스윙 토크 2.53 배 초과의 주범은 `M q̈` 가 아니라 임피던스 `Jᵀ F` 다**
  ⚠ **정정 (9/22 Q13)**: 스윙 토크 초과의 진짜 원인은 **이륙 첫 틱의 스윙 시작점 버그**였다 — 시작점이 한 틱 늦게 기록돼 스윙 제어기가 한 주기 전 위치(~40 cm 뒤)를 목표로 400 N 을 냈다. 고친 뒤 스윙 토크 초과 1.9 % → **0 %**.

> **수정된 판정**: `J̇q̇` 보상은 **식을 옳게 만드는 작업**이지 병목 해소가 아니다.
> 측정된 이득은 "첨두 q̈·토크 26 % 감소" 정도. **우선순위는 낮다.**
> (토크 초과를 잡으려면 임피던스 쪽 클램프가 맞는 자리)

### ③ 골반 행 — 앞선 내 설명 정정

운동방정식을 골반(b)과 관절(j)로 나누면:

```
[M_bb M_bj][q̈_b]   [h_b]   [ 0 ]   [J_bᵀF]
[M_jb M_jj][q̈_j] + [h_j] = [ τ ] + [J_jᵀF]
                             ↑ 위 6행에는 τ 가 없다
```

**위 6행에 모터가 없는 것이 부족구동(underactuation)** 이다. 골반의 운동은
**중력과 접촉력만으로** 결정된다.

그러니 `tau = qfrc_bias[adof] + tau_c[adof]` 로 아래 행만 쓰는 건
**"버리는" 게 아니라 애초에 쓸 수 없는 행**이다 (내가 "버려집니다"라고 한 건 부정확).

**진짜 문제는 다른 데 있다**: 위 6행이 말하는 **"스윙 반작용이 골반에 주는 영향"을
MPC 가 모른다.** SRB 는 다리를 무게 없다고 보니까. `--swingid` 는 **관절 수준의 실현**을
고치지만 **MPC 의 모델 자체**는 못 고친다.
→ 9/16 Q8 의 골반 흔들림과 같은 뿌리이고, `L_다리` 아핀항 제안이 노리던 지점이다.

## Q3. `Caron 사각 접촉` 은 어디서 온 것인가 — 출처를 제대로 파보자

### 1. 출처

> **S. Caron, Q.-C. Pham, Y. Nakamura**, *"Stability of Surface Contacts for Humanoid
> Robots: Closed-Form Formulae of the Contact Wrench Cone for Rectangular Support Areas"*,
> **ICRA 2015**, pp. 5107–5112. [arXiv:1501.04719](https://arxiv.org/abs/1501.04719)

PDF 를 받아 대조함. 우리가 쓰는 건 **Proposition 2 (식 15–20)** 전부다:

```
|fx| ≤ μ fz                                    (15)  ┐ Coulomb 마찰
|fy| ≤ μ fz                                    (16)  ┘
fz > 0                                         (17)  ┐
|τx| ≤ Y fz                                    (18)  ├ ZMP(CoP) 조건과 동치
|τy| ≤ X fz                                    (19)  ┘
τmin ≤ τz ≤ τmax                               (20)  ← ★ 논문의 새 기여

τmax = +μ(X+Y)fz − |Y fx + μτx| − |X fy + μτy|
τmin = −μ(X+Y)fz + |Y fx − μτx| + |X fy − μτy|
```

논문 주장: (i)(ii) 는 기존에 알려진 것이고 **(iii) 요 토크 상한이 새롭다**
("condition (iii) is, to the best of our knowledge, novel").

### 2. 왜 8행인가

`|a| = max(a, −a)` 이므로 부호를 나열하면 절댓값이 선형 부등식이 된다:

```
τz ≤ τmax  ⟺   τz + s₁(Y fx + μτx) + s₂(X fy + μτy) ≤ μ(X+Y)fz   ∀ s₁,s₂∈{±1}  (4행)
τz ≥ τmin  ⟺  −τz + s₁(Y fx − μτx) + s₂(X fy − μτy) ≤ μ(X+Y)fz   ∀ s₁,s₂       (4행)
```

**식 (20) 하나를 선형화한 것.** 2개 절댓값 × 각 2부호 × 2(상·하한) = 8.

### 3. 우리가 추가로 한 것 — **좌표 이동** (논문에 없음)

논문은 wrench 를 **사각형 중심 O** 에서 계산한다고 전제한다
("We calculate the contact wrench W at the center O in the link's RF").

그런데 우리 wrench 는 **발목 site** 기준이고 G1 발은 **비대칭**이다 (앞 12 / 뒤 5 cm).
중심은 발목보다 `x_c = (l_t−l_h)/2 = 3.5 cm` 앞, `h = 3.5 cm` 아래.

wrench 이동 `τ_O = τ_site − r × f`, `r = (x_c, 0, −h)` 를 풀면:

```
τx = mx − h·fy
τy = my + h·fx + x_c·fz
τz = mz − x_c·fy
```

[mpc_qp.py](../MPC/src/mpc_qp.py) `foot_constraints` 와 **완전히 일치**.
논문을 베낀 게 아니라 **우리 발 형상에 맞게 좌표를 옮긴** 것.

### 4. ★★ 논문에 우리 문제를 직접 겨냥한 문장이 있다

> "**higher tangential forces or roll-pitch torques reduce the range of admissible yaw
> torques.** In particular, **when these other constraints are saturated** (for instance
> when the ZMP reaches a corner of the support polygon), **τ_safe is the only solution**
> that prevents the contact from breaking. Therefore, **τz = τ_safe appears as a sensible
> control law to prevent undesired yaw rotations.**"

그리고 `τ_safe` 는 **0 이 아니다**:

```
τ_safe = (τmin+τmax)/2 = sgn(−fx·τx)·min(Y|fx|, μ|τx|) + sgn(−fy·τy)·min(X|fy|, μ|τy|)
```

### 5. 재봤다 — **허용 폭이 속도와 함께 닫힌다**

25 s, 권장 구성, stance 샘플:

| vx | 허용 폭 `τmax−τmin` | **폭 < 0.5 Nm 비율** | τ_safe RMS | 우리 τz RMS | \|τz−τ_safe\| / (폭/2) |
|---|---|---|---|---|---|
| 0.3 | **20.34 Nm** | **0.0 %** | 2.21 | 1.45 | 13 % |
| 0.5 | 13.35 Nm | **9.5 %** | 3.07 | 3.32 | 47 % |
| 0.6 | **9.16 Nm** | **23.8 %** | 3.61 | 3.97 | **50 %** |

**논문이 예측한 그대로다.** 접선력·롤피치 토크가 포화될수록 요 토크 허용 구간이 좁아진다.

- **0.3 → 0.6 에서 폭이 2.2배 줄어든다** (20.3 → 9.2 Nm)
- **0.6 에서는 24 % 의 시간 동안 폭이 0.5 Nm 미만** — 최솟값 0.000, 즉 **요 모멘트가 완전히 핀 고정**
- 우리 명령 τz 는 남은 반폭의 **47~50 %** 를 쓰고 있다 (0.3 에선 13 %)

### 6. 무엇을 설명하고 무엇을 설명 못 하나

**설명하는 것**: 9/16 에 잰 `mz(Caron)` 행 활성률 11~18 %(0.6) 의 정체.
그리고 **고속에서 MPC 의 자유도가 줄어드는 또 하나의 경로** — CoP 포화가
직접 CoP 를 막을 뿐 아니라 **요 토크까지 같이 조인다** (결합 제약이므로).

**설명 못 하는 것**: 직진 중 발이 20° 도는 현상. 그건 9/16 Q2 에서
**스윙 단계의 발 yaw 정렬**(`--swingyaw`)로 0.68° 까지 잡았고, 위 측정은
그 플래그가 켜진 상태다. 즉 20° 는 stance 미끄러짐이 아니라 배치 문제였다.

### 7. 후보 — 우리 cost 는 τ_safe 를 **모른다**

`R = 1e-5` 가 wrench 전 성분에 균일하게 걸려 있어 **mz 를 0 으로 당긴다.**
그런데 τ_safe 의 RMS 가 3.1~3.6 Nm 다 — **cost 가 가장 안전한 점에서 멀어지는
방향으로 당기고 있다.**

τ_safe 는 wrench 자신의 함수라 그대로 넣으면 비선형이지만,
**직전 해의 wrench 로 계산해 참조값으로 쓰면**(1스텝 지연) QP 는 선형으로 유지된다.
→ **미검증 후보.**

> **예측(검증 가능)**: 허용 폭이 좁아지는 건 `|X fy + μτy|` 등 때문이므로,
> **보폭을 좁혀 횡 CoP 부담을 낮추면 요 허용 폭도 같이 넓어져야 한다.**
> 보폭 작업(1순위) 후 이 표를 다시 재면 가설을 바로 확인할 수 있다.

## Q4. 접촉 제약 18행 전체 — 처음부터 다시

> "이 제약조건들 다시 공부해야겠다"
> 자기완결적으로 쓴다. 이 절만 읽어도 18행이 각각 뭘 막는지 알 수 있게.

### 0. 왜 제약이 필요한가 — **MPC 는 지면에 부탁하는 입장이다**

MPC 가 계산하는 `u = W = [Fx, Fy, Fz, mx, my, mz]` 는 **지면이 발에 가해주길 바라는 힘**이다.
그런데 지면은 아무거나 안 해준다:

- **당길 수 없다** (밀기만 가능)
- **미끄러진다** (마찰 한계)
- **발 밖을 누를 수 없다** (발이 닿은 데만 힘이 난다)
- **비틀림도 마찰로만 낸다**

제약이 없으면 MPC 는 **실현 불가능한 계획**을 세우고, 실제로는 다른 힘이 작용해서
"명령 wrench ≠ 실현 wrench" 가 된다. 실제 사례: 회전 시 mz 무제약이었을 때
MPC 가 **143 N·m 를 비틀겠다**고 계획 → 지면이 못 줌 → 요 추종오차 −11.3°
(MPC_NOTES 18.4). Caron 제약 넣고 −1.4° 로 잡혔다.

l_h   = 0.05 m     발목 → 뒤꿈치 (뒤)      ← 앞뒤 비대칭!

### 2. 18행 전체 ([mpc_qp.py](../MPC/src/mpc_qp.py) `foot_constraints`)

#### (a) 마찰 4행 — "안 미끄러진다"

```
 Fx ≤ μFz      −Fx ≤ μFz       Fy ≤ μFz      −Fy ≤ μFz
```

진짜 조건은 **원뿔** `√(Fx²+Fy²) ≤ μFz` 인데, 이건 비선형이라 QP 에 못 넣는다.
**사각뿔로 근사**한다 (각 축을 독립으로 제한).

> ⚠ **대각 방향에서 √2 배(41 %) 낙관적**이다. 직진에선 Fy 가 작아 무해했지만
> **회전에서 유해 확정** — 실측 `|F_xy|/Fz = 0.849 = √2 × 0.6` (MPC_NOTES 18.2b).
> 미해결 항목.

#### (b) Fz 2행 — "밀기만, 그리고 적당히"

```
 Fz ≤ 500        −Fz ≤ −10   (= Fz ≥ 10)
```

- **하한 10 N**: 접촉을 유지하라는 뜻. 0 이면 QP 가 "발을 뗀다"는 해를 낼 수 있다
- ⚠ 이 하한이 9/16 Q3 의 문제를 만든다 — **스케줄상 착지 시각에 발이 아직 공중**인데
  (softland 에서 접촉률 0 %) MPC 는 이미 10 N 이상을 요구한다

#### (c) CoP 4행 — "발바닥 안에서만 누른다" ★ 우리 병목

**CoP(Center of **Pressure**, 압력중심)** = 지면 반력 전체가 한 점에 작용한다고 볼 때 그 점.
**발바닥 밖으로 못 나간다** — 발이 지면을 당길 수 없으므로.

```
롤 (좌우):   mx − h·Fy ≤  w·Fz          −(mx − h·Fy) ≤ w·Fz
피치 (앞뒤): my + h·Fx ≤ l_h·Fz         −(my + h·Fx) ≤ l_t·Fz
```

```
        발바닥 위에서 본 모습
        ←─── 앞 12 cm ───→
   ┌────────────────────────┐  ↑
   │   CoP 는 이 안에서만   │ 2.5 cm   ← 좌우가 5배 좁다
   └────────────────────────┘  ↓
   ←5cm→
```

**★ `h·Fx`, `h·Fy` 결합항이 왜 있나** (검증 리포트 §1 에서 잡은 버그):
wrench 는 **발목 site** 에서 정의되는데 CoP 조건은 **발바닥**(3.5 cm 아래) 기준이다.
지면으로 옮기면 `m_ground,y = my + h·Fx`, `m_ground,x = mx − h·Fy`.
**수평력이 3.5 cm 팔길이로 CoP 를 밀어낸다.**

크기: `|Fx| = μFz` 일 때 `h·μ = 0.021·Fz` — 롤 마진(0.025Fz)의 **84 %**,
뒤꿈치 마진(0.05Fz)의 42 %. **가속 중(Fx>0)에 뒤꿈치 권한을 과대평가 → 후방 전도.**
서 있기(Fx≈0)에선 0 이라 Step 1 검증에서 안 잡혔다.

#### (d) Caron mz 8행 — "비틀림도 마찰 예산을 쓴다"

출처: **Caron, Pham, Nakamura, ICRA 2015** ([arXiv:1501.04719](https://arxiv.org/abs/1501.04719)),
Proposition 2 식 (20). 자세한 유도는 **Q3** 참고.

사각 중심 기준 (`X=0.085, Y=0.025, x_c=0.035`) 으로 옮긴 뒤:

```
τx = mx − h·fy        τy = my + h·fx + x_c·fz        τz = mz − x_c·fy

τz ≤ +μ(X+Y)fz − |Y·fx + μτx| − |X·fy + μτy|      → 부호 전개 4행
τz ≥ −μ(X+Y)fz + |Y·fx − μτx| + |X·fy − μτy|      → 부호 전개 4행
```

**핵심 개념: 마찰은 공유 예산이다.** 앞으로 밀고(Fx), 옆으로 밀고(Fy), 비트는(mz) 게
**같은 마찰을 나눠 쓴다.** 이미 세게 밀고 있으면 비틀 여력이 없다.
`−|...|` 두 항이 정확히 **"접선력이 먹은 예산을 빼라"** 는 뜻이다.

### 3. 실제로 어느 게 걸리나 (25 s 실측, 1.0 = 포화)

| 제약 | vx 0.3 | vx 0.5 | vx 0.6 |
|---|---|---|---|
| **롤 CoP** (평균 / >0.9 비율) | 0.87 / **60 %** | 0.75 / **50 %** | 0.79 / **63 %** |
| **피치 CoP** | 0.90 / **58 %** | 0.92 / **68 %** | 0.91 / **61 %** |
| 마찰 | 0.30 / 0 % | 0.34 / 0 % | 0.44 / 7 % |
| mz (행 활성률) | 7~13 % | — | 11~18 % |
| **mz 허용 폭** `τmax−τmin` | 20.3 N·m | 13.4 | **9.2** (24 % 가 0.5 미만) |

> ⚠ **2026-09-21 정정 — 이 표의 롤·피치 CoP 는 월드 frame 으로 계산됐다.**
> 제약은 **몸 yaw frame** 에서 걸리는데(`C·Rzᵀ W`), `ctl.wr` 의 월드 `mx` 를 그대로 썼다.
> `my`(±30 N·m)가 롤 예산(8 N·m)보다 훨씬 커서 **yaw 가 몇 도만 틀어져도 "mx" 로 새어든다**
> (5° → 2.6 N·m = 예산의 32 %). yaw frame 으로 회전해 다시 재면 0.5 m/s 에서
> **평균 0.73, >0.9 비율 28 %** (위 표의 0.75 / 50 % 중 **평균은 유효, 비율은 과대**).
> 0.6 은 0.83 / 45 %. 재측정 스크립트: [13_sidew_ab.py](../MPC/src/13_sidew_ab.py).

**읽는 법**:
- **CoP 두 개가 지배적**이고 **0.3 m/s 에서 이미 포화**다. 속도만의 문제가 아니다
- **마찰은 병목이 아니다** — 미끄러짐 걱정은 안 해도 된다
- mz 는 단독으로 크진 않지만 **CoP 포화가 mz 허용 폭까지 같이 조인다**
  (결합 제약이므로) — 0.6 에서 폭이 2.2배 줄고 24 % 는 완전 폐쇄

### 4. reference 와의 차이 — **같은 수식, 다른 숫자** (9/18 발견)

수식 구조는 같다. `footHalfWidth` 가 쓰이는 자리도 동일하다
([ConvexMPC.cpp:173-176](../reference/My_Controller/src/ConvexMPC.cpp#L173-L176)).
파라미터는 G1 전용으로 **따로 튜닝**했다 (타이밍·가중치·스윙 전부 다름).

**그런데 발 치수가 물리와 어긋난다**:

| | 실제 G1 발 (그들이 쓰는 4구 모델 = 우리와 동일) | **그들 설정** |
|---|---|---|
| half_length | 0.085 m | 0.15 (1.8배) |
| **half_width** | **0.025~0.03 m** | **0.35 (약 12배)** |

`Fz=327 N` 에서 허용 롤 모멘트가 **±8.2 (물리) vs ±114 N·m (그들 설정)**.
**롤 CoP 제약이 사실상 풀려 있다** — 속도 제한을 1000 km/h 로 세워둔 것과 같다.
(MIT 설정 0.065/0.01 은 그들 발과 잘 맞는다. **G1 쪽만 어긋남** — 오타인지 의도인지는 불명)

> **함의**: MPC_NOTES 24절이 *"reference 는 같은 G1 으로 0.6 m/s 를 하는데 왜 우리는"*
> 을 동기로 삼았는데, **같은 조건의 비교가 아니었다.** 우리는 w=0.025 (그것도 접촉점
> 최솟값을 쓴 보수적 값)로 조이고 그 벽에 부딪히는 중이고, 그들은 벽을 12배 멀리 세웠다.
>
> 대신 **배포 RL 정책의 1.28 m/s 는 제약 없이 물리 시뮬만으로 나온 진짜 상한**이므로
> (9/17), 비교 기준으로는 그쪽이 훨씬 신뢰할 만하다.

### 5. 검증 방법 — LP 존재성으로 판정한다

`10_constraint_check.py` 가 18행 전체를 **4점 사각 접촉 LP 와 대조**한다
(2500샘플 × yaw 2종, **100 % 일치**).

> ⚠ **함정**: "어떤 점힘 배분이 제약을 위반한다" ≠ "그 wrench 가 실현 불가능하다".
> 4점에 힘을 어떻게 나누느냐는 자유다. **정답 판정은 "그런 배분이 존재하는가"(LP 존재성)**
> 로 해야 한다. 부호도 기억이 아니라 이 대조로 확정했다 (MPC_NOTES 18.5).
