## Q1. 비대칭이 안 고쳐지는 이유 — MPC 가 '없는 roll 모멘트' 로 바로잡으려 한다 + mx = 0 (`foot=mx0`) A/B

**결론** (측정): ref 발 모델에서 MPC 는 두 발 모두 **같은 부호의 roll 모멘트** (평균 −0.75 N·m) 를 계속 요청하고,
위상을 맞바꾸면 (`sideswap`) 부호도 같이 뒤집힌다 — 쏠림을 발목 roll 로 바로잡으려는 명령인데 **선 접촉 발은 이걸 못 준다**
(9/26 Q5·9/25 논의). MPC 는 고치고 있다고 믿지만 실제로는 사라진다 → 비대칭이 유지된다 (추론).
mx = 0 등식만 넣으면 (`mx0`) 걷기가 무너지고 (0.6 에서 17 s, 추종 67 %), **mx0 + 착지 속도 되먹임 (rai 0.2)** 이면
네 목표 모두 완주하며 **전진 하중비 1.38 → 1.11** 로 대칭에 가까워진다.

### 2. 덤 — 서기 수정 (9/26 Q6) 이 걷기 시작을 바꾸고 있었다 → 수정

걷기도 시작 전 1 s StandingSettle (FSM 서기) 를 거치는데, Q6 의 서기 yaw hold · 자중 보상이 거기에도 걸려
시작 자세가 조금 달라졌고 **0.6 m/s 가 20.0 s 에 전도** (재현 확인). 서기 수정은 **서기가 요청된 경우만** 걸도록
([controller.py](../MPC/src/casadi_mit/controller.py) `stand_fix`) → 걷기 0.6 원래 궤적 복귀 (120 s · 85 %), 서기 드리프트 2.7 mm 유지.
덤의 교훈: **0.6 m/s 는 시작 자세 변화에 20 s 로 넘어질 만큼 경계에 있다** (명령 1e-4 흔들림엔 버텼지만).

### 4. 읽기

- **mx0 단독이 무너지는 이유 (추론)**: roll 통로를 막으면 MPC 에 옆 방향 복원 수단이 거의 없다 (선 발이라 CoP 도 옆으로 0).
  남는 건 착지 위치뿐인데 reference 착지 계획엔 측정 속도 항이 없다 (9/26 Q8) → 옆 되먹임 0 → 느려지고 넘어짐.
- **mx0 + rai 가 맞는 짝**: 물리적으로 불가능한 통로 (roll) 를 막고, 실제로 가능한 통로 (발걸음) 에 되먹임을 준다.
  **전진 하중비 1.11** 로 비대칭 대부분 해소, 세 목표 유지. 추종은 rai 단독 (92 %) 보다 약간 낮다 (89 %).
- **남은 것**: vy −0.05 옆 드리프트 (속도 되먹임뿐이라 위치는 안 잡음). 회전 τ/lim 스파이크 1400 (1 회 순간값, 포화 비율 0.32 는 다른 구성과 같음).
- **판단**: mx0 + rai 0.2 를 **채택 후보** — 렌더 확인 (`--foot mx0 --rai 0.2`) 후 casadi_mit 기본값 전환 결정. 기본은 아직 ref · rai 0.
