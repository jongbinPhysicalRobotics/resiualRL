## Q1. (교수님 피드백) sin 스윙궤적은 탕 튀거나 내리꽂는 식이 된다

> 다른 팀 발표에서 나온 지적. 베지어로 보완하면 될 것 같다. **수정은 하지 말고 인지·기록만.**

### 지적이 정확히 맞고, 우리는 이미 재봤다

sin 아치 `z = h·sin(πs)` 의 양 끝 속도는 `±h·π/T_sw` 로 **0 이 아니다**:
- 이륙(s=0): **+0.457 m/s** ← "탕 튀는" 것
- 착지(s=1): **−0.457 m/s** ← "내리꽂는" 것 (T_sw=0.344, h=0.05 기준)

9/16 Q3 에서 실측: sin 아치 명령 −0.457 / 실제 −0.512 m/s.

### 현재 상태 — `--softland` 가 양 끝을 이미 0 으로 만든다

| | 이륙 v_z | 착지 v_z |
|---|---|---|
| sin (코드 **기본값**) | +0.457 | −0.457 |
| `--softland` (권장 구성) | **0** (smoothstep) | **0** (Hermite, v_td=0) |

권장 구성엔 이미 들어 있다. 다만 **코드 기본값은 아직 sin** (`soft_land=False`) 이라
플래그 없이 돌리면 교수님이 지적한 그 궤적이 나온다.

### 베지어와의 관계 — 9/16 Q3 에서 정량 비교함

같은 경계조건(v_to=v_td=0, 정점 5 cm)으로 5차 베지어와 우리 2단 곡선을 비교하면
**양 끝은 정확히 일치**하고 최대 편차 1.74 cm 는 스윙 중반(s=0.73). 접촉 구간 편차는
0.4~0.6 cm 로 실측 추종오차(1.6~5.6 cm)에 묻힌다.
→ **곡선족은 무관, 경계조건이 전부.** 베지어로 바꿔서 얻는 건 **`v_to` 파라미터**
(의도적 이륙속도로 초반 clearance 확보 — 현재 0.89 cm 로 빠듯) 하나다.

> **정리**: 교수님 지적 = 우리 9/16 Q3 결론과 일치. 착지 쪽은 해결됐고, 이륙 쪽
> `v_to` 는 미검증 후보로 남아 있다. 오늘은 수정 안 함.

## Q2. (교수님 피드백) dt = 0.02, 즉 50 Hz 까지는 잘 나와야 한다

> **인지·기록만.**

### 현재 우리 주기

| | 값 |
|---|---|
| 물리 시뮬 | 500 Hz (dt 0.002) |
| 토크 갱신 (Jᵀ·임피던스) | 500 Hz |
| **MPC 재풀이** | **100 Hz** (`DECIM=5`) |
| MPC 지평 이산화 `DT_MPC` | 0.05 s × 16 = 0.8 s |

"dt=0.02" 는 **재풀이 주기**로 읽는 게 자연스럽다 (지평 이산화는 이미 0.05).

### 참고 근거 둘

- **배포 RL 정책은 50 Hz** (`control_decimation=10` × 0.002) 로 1.28 m/s 를 간다 (9/17)
- Residual MPC 논문 Fig. 7: MPC 를 **25 Hz** 로 내리면 학습이 크게 나빠진다 (100 Hz 필수)
  → 50 Hz 는 그 사이. 논문은 50 Hz 를 시험하지 않았다

### 시험 방법 (나중에)

`--decim 10` 한 플래그. 현재 QP 평균 7.8 ms / p99 11.7 ms 라 **계산 여유는 50 Hz 에서
2.5배**로 늘어난다. 붕괴한다면 계산이 아니라 **지연 위상여유**(PHYSICS_MAP 230행:
자세루프 ~3 Hz, 지연 ~25 ms) 문제일 것.

`v.user_scn` 사용. 뷰어 없이 독립 `MjvScene` 으로 검증함 (스윙 중 26 geom/발).

**① 토크 스파이크가 눈에 보인다.** hip_pitch 가 **스윙마다 한 번씩 −200 N·m** 까지 튀고

이제 그림으로 보인다.

**② 스윙 추종오차가 톱니다.** 이륙 때 0 → 착지 때 **4~5.6 cm** 로 단조 증가.

스윙 중에 쓸리기 때문이다 (9/16 Q1: 14 cm) — **과녁이 움직여서 생기는 오차**라는

**③ 솔브타임은 이봉(bimodal).** 서 있을 때 ~5 ms, 걸을 때 ~8 ms (활성 제약 증가).

**④ R_my 가 +20 N·m 까지** — 피치 CoP 예산 +16.4 N·m(Fz=327 기준)를 넘는 순간이 있다.

## Q4. 스윙궤적 기준점 — 사각형(발바닥) 중심으로 잡을까?

> 내 의견 → **발 site(발목 원점) 유지. 이유 셋.**

### ① 제어기가 추종하는 점이 발목이다

`SwingController.wrench()` 는 `mj_jacSite(발 site)` 로 자코비안을 구하고 거기에
임피던스를 건다. **궤적은 제어기가 실제로 움직이는 점에 정의해야** 추종오차가
의미를 갖는다. 사각형 중심에 궤적을 정의하고 발목을 제어하면 "명령한 점 ≠ 제어한 점".

### ② 발이 수평이면 두 점은 상수 오프셋이다

스윙 제어기가 발바닥을 수평으로 유지하므로(z축 정렬 모멘트), 발바닥 중심은
발목에서 **앞 3.5 cm · 아래 3.5 cm 고정** (`x_c = 0.035, h = 0.035`, 발 frame).
궤적·추종오차 **그림 모양이 같고 위치만 평행이동**한다. 정보가 늘지 않는다.

### ③ 사각형 중심은 "다른 질문"의 답이다

Caron CWC 가 사각형 중심을 쓰는 건 **접촉 wrench 의 기준점**(힘이 어디에 작용하나)이
그래야 식이 닫히기 때문이다 (9/18 Q3). 스윙궤적은 **기구학적 목표**(발이 어디로 가나)다.
같은 점을 쓸 이유가 없다.

### 그래도 발바닥 중심이 필요해지는 경우

- **발이 스윙 중에 피치**하면 발가락·뒤꿈치 clearance 가 발목 높이와 달라진다
  (험지, 계단). 그땐 `foot_pos` 에 발가락·뒤꿈치 z 를 따로 추가 (3줄)
- 착지 목표 `z_ground = 0.0331` 은 이미 "발바닥이 닿을 때의 발목 높이"라
  오프셋을 품고 있다 — 지금은 문제없음

> **적용**: 뷰어·로그 모두 **발 site 기준**. 코드 주석에 근거 명시.
> 이 프로젝트의 반복 교훈(닫힌 루프를 불필요하게 건드리지 않기)과도 맞는다.

## Q5. 착지~stance 구간의 u 로그 분석 — 접촉이 제대로 안 되는 것 아닌가?

> 새 스크립트 [12_contact_analysis.py](../MPC/src/12_contact_analysis.py).
> 스케줄 착지 시각을 t=0 으로 43개 스텝을 정렬해 평균.

### 결론: **접촉은 빨리 된다. 문제는 "하중 인계(handoff)"에 구멍이 뚫리는 것.**

### 1. 접촉 확립 자체는 문제가 아니었다

| | 값 |
|---|---|
| 실제 접촉까지 지연 | 평균 **6.0 ms**, 중앙값 4.0, 최대 12.0 |
| 미접촉 이벤트 | **0 / 43** |
| stance 전체 실현율 (실측/명령 Fz) | **98 %** |
| 초기 50 ms 실현율 | 99 % |

> 9/16 Q3 의 "8.5 ms 늦게 닿는다"는 맞았지만, **그 자체는 병목이 아니다.**
> 100 ms 이후로는 명령과 실측이 ±5 N 으로 붙고 `my` 도 거의 완벽히 추종한다.

### 2. ★ 그런데 착지 후 첫 100 ms 가 심하게 진동한다

| 스케줄 대비 | 착지발 실측 | 반대발 실측 | **합계 / 체중** |
|---|---|---|---|
| −8 ms | 0 N | 325 N | 99 % |
| **0 ms** | **0 N** (명령 **219 N**) | 310 N | 95 % |
| +16 ms | 336 N | 88 N | **130 %** |
| +48 ms | 250 N | 58 N | 94 % |
| **+64 ms** | **104 N** | **0 N** | **⚠ 32 %** |
| **+72 ms** | **466 N** | 0 N | **142 %** |
| +96 ms 이후 | ~330 N | 0 N | ~100 % (안정) |

**+64 ms 에 양발 합력이 체중의 32 % 로 떨어진다 — 몸이 순간적으로 거의 자유낙하한다.**
그리고 8 ms 뒤 142 % 로 내리꽂힌다. 합력 최대는 평균 **160 %**, 최악 **191 %**.

### 3. 기전 — 인과 사슬

1. **스케줄 착지 시각에 MPC 가 공중의 발에 219 N 을 명령** (실측 0 N, 발 높이 1.4 mm)
   — `Fz ≥ 10 N` 제약 때문에 QP 가 그 발에 하중을 배분한다
2. 그 명령이 `−JᵀW` 로 **다리를 아래로 가속**시킨다 (임펄스 219 N × 6 ms ≈ 1.3 N·s,
   다리 7.2 kg 기준 Δv ≈ 0.18 m/s — 원래 착지속도 0.048 m/s 의 4배)
3. 6 ms 뒤 접촉이 생길 때 **여분의 운동량**이 있어 Fz 가 오버슛 (명령 236 → 실측 323 N)
4. 오버슛 → **발이 튄다** (관통 −1.1 mm → 반발 +2.2 mm)
5. 그 사이 **반대발은 스케줄대로 +56 ms 에 떠난다** (DS = 2·sf−1 = 14 % = 112 ms/주기,
   착지 후 몫은 56 ms)
6. **+64 ms: 새 발은 튀어올라 104 N, 반대발은 0 N → 합력 32 %** — 몸이 떨어진다
7. 떨어진 몸이 발을 다시 눌러 **466 N (142 %)**, ~96 ms 에 안정

> **명령 합력은 내내 327~374 N (≈체중) 으로 정상이다.** 계획이 아니라 **실현**의 문제다.

### 4. 배포 RL 정책과 비교 — 정반대 성향

| | 착지 v_z | **합력 최대** | **합력 최저** |
|---|---|---|---|
| **우리 MPC** (0.5) | **−0.048 m/s** | 160 % (최악 191) | **⚠ 32 %** |
| 배포 RL (0.5) | −0.490 m/s | 208 % (211) | **92 %** |
| 배포 RL (1.0) | −0.001 m/s | 226 % (232) | 70 % |

**우리는 10배 부드럽게 착지하는데(−0.048 vs −0.490) 하중이 끊긴다.**
**그들은 세게 착지하지만 하중이 한 번도 92 % 아래로 안 내려간다.**

> **즉 "부드러운 착지"를 얻고 "연속적인 하중 인계"를 잃었다.**
> 9/16 Q3 에서 `--softland` 도입 후 저속 pitch 가 후퇴한 것의 진짜 정체가 이것으로 보인다.
> (그때는 "접촉률 42→0 %" 로만 봤는데, 실제로 아픈 건 **합력 32 % 구멍**이다)

### 5. 무엇을 고쳐야 하나 — 우선순위 수정

9/16 Q3 에서 "접촉 인지 계층" 3종(Fz,min 램프 / 실측 접촉 N_lock / 지면 탐색)을 적었는데,
**이 측정은 그중 어느 것이 급한지를 가른다**:

1. **★ `Fz,min` 램프가 1순위** — 착지 직후 `Fz ≥ 10 N` 을 즉시 요구하지 말고
   `α(t)·Fz_min` 으로 올린다. 사슬의 **1번 고리(공중 발에 219 N)를 끊는다**
2. **이중지지 구간 재검토** — 반대발이 뜨는 시각(+56 ms)이 새 발의 하중 인수보다 이르다.
   `sf` 를 키우면 DS 가 늘지만 9/17 데이터는 반대(고속일수록 sf ↓)를 가리킨다.
   → **램프로 인수를 앞당기는 쪽이 먼저**
3. 실측 접촉 기반 스케줄 보정은 그다음

> ⚠ 이 프로젝트 전례상 **증상을 직접 누르면 하중받던 것이 드러난다.**
> `v_td` 로 착지속도를 키우는 건 이미 실패했고(9/15), 이번 데이터도
> **충격이 아니라 연속성이 문제**라고 말하므로 그 방향은 여전히 아니다.

## Q6. `J̇q̇` 를 넣어봤다 — **6번째 "증상 억제의 역설"**

> "어차피 큰 도움이 안 된다면 그냥 정의를 잘 사용하는 게 맞을 것 같다"
> → 타당한 원칙이라 구현. **그런데 '도움이 안 되는' 게 아니라 '손해'였다.**

### 1. 구현

`mj_jacDot` 이 MuJoCo 3.12 에 있고 비용도 **1.5 us** (500 Hz 발 2개 = **+0.15 %**).

```python
rhs = [a_ff, 0]
if self.jdot:
    mujoco.mj_jacDot(m, d, jdp, jdr, d.site_xpos[sid], m.site_bodyid[sid])
    rhs -= np.vstack([jdp, jdr])[:, dofs] @ d.qvel[dofs]    # p̈ = J q̈ + J̇ q̇
qdd = lstsq(J6, rhs)
```

### 2. 의도한 효과는 **났다**

| vx | `J̇q̇` | **z 추종오차** | **스윙토크 최대배** |
|---|---|---|---|
| 0.5 | 켬 | **0.21 cm** | **2.31** |
| 0.5 | 끔 | 0.25 | 2.53 |
| 0.6 | 켬 | **0.21** | **2.41** |
| 0.6 | 끔 | 0.24 | 2.55 |

z 추종 **16 % 개선**, 스윙토크 첨두 감소. 앞서 예측한 방향 그대로.

### 3. ★ 그런데 횡 진동이 **5/5 속도 전부** 악화한다

40 s A/B, 다섯 속도:

| vx | y진폭 (jdot) | y진폭 (off) | **변화** | 실측 v (jdot / off) |
|---|---|---|---|---|
| 0.2 | 3.4 | 3.4 | **+0 %** | 0.199 / 0.199 |
| 0.3 | 3.6 | 3.3 | +6 % | 0.306 / 0.307 |
| 0.4 | 3.6 | 3.3 | +10 % | 0.410 / 0.412 |
| 0.5 | 5.2 | 4.2 | +23 % | 0.494 / 0.496 |

**평균 +14 %, 5/5 악화, 그리고 속도에 단조 증가.**
120초 배터리(0.3/0.5/0.6)도 전부 생존은 하나 같은 경향.

> 단조 증가가 결정적이다 — 궤적 의존 노이즈라면 이렇게 깔끔하게 속도에 비례하지 않는다.

### 4. 기전 추정 — **횡 여유가 없어서 드러난다**

- `J̇q̇` 보상은 `q̈` **평균을 68.5 → 79.0 으로 키운다** (첨두는 267→220 으로 줄이지만)
- `M` 은 밀집이라 `M q̈` 는 **stance 다리·골반 행에도** 값을 만든다
  → 평균이 커지면 **stance 로 가는 교차항도 평균적으로 커진다**
- 그런데 **롤 CoP 는 0.3 m/s 부터 이미 포화**(이용률 1.13, 9/18 Q4). 여유가 없다

**0.2 m/s 에서 차이가 정확히 0 인 것이 이 해석을 지지한다** — 그 속도엔 횡 여유가 있다.
즉 `J̇q̇` 가 틀려서가 아니라 **닫힌 루프의 횡 마진이 바닥이라 어떤 교란도 증폭**된다.

### 5. 판정 — **기본 꺼짐, 플래그 보존, 보폭 후 재시험**

```
--jdot     (opt-in, 기본 꺼짐)
```

- **식 자체는 `--jdot` 쪽이 옳다.** 주석에 근거와 측정치를 남겼다
- 지금 끄는 이유는 "틀린 식이 좋아서"가 아니라 **"현재 닫힌 루프가 그쪽에 co-adapt 돼
  있고, 정확한 식이 요구하는 횡 마진이 지금 없어서"**
- **1순위 보폭 축소(27→16 cm)로 횡 CoP 여유가 생기면 결론이 바뀔 수 있다.**
  그때 이 표를 그대로 다시 돌릴 것

> **이 프로젝트에서 6번째**다: capy / LIP-exact / td_mode / 제약 frame / 상체 SRB / **J̇q̇**.
> 다만 앞의 다섯과 성격이 다르다 — 앞의 것들은 **제어 법칙·제약 집합**을 바꿔
> 평형점을 옮겼지만, 이건 **피드포워드 한 항**이고 문제는 그 항이 아니라
> **그 항을 감당할 마진이 없다는 것**이다. **조건부 보류**로 기록한다.

## Q8. 착지 후 발 앞부분이 잠깐 올라왔다 다시 닿는다 — 왜?

> 뷰어에서 직접 관찰: "발이 붙고 나서 갑자기 발 앞부분이 잠깐 올라왔다가 다시 땅에 닿는다."
> 계측: [14_toe_lift.py](../MPC/src/14_toe_lift.py) — 발가락·뒤꿈치 접촉구를 **따로** 본다 (착지 35회 평균).

### 1. 현상 — 생각보다 크다

| | 값 |
|---|---|
| **발가락 최대 들림** | **평균 26.1 mm, 최대 45.0 mm** |
| 발 pitch | 평균 곡선 **−9.0°**, 스텝별 최소의 평균 −9.5° (발끝이 위로) |
| 발가락 하중이 0 인 구간 | 착지 **+64 ~ +170 ms**, 스텝당 평균 **114 ms** |
| 명령 CoP x 의 최대 점프 | 스텝당 평균 **17.0 cm** (발 길이 전체) |
| 다시 닿을 때 | pitch +3.5°, 발가락이 지면을 **11 mm 파고듦** (≈350 °/s 로 내리찍음) |

### 2. 타임라인

| 착지 후 | 발가락 Fz | 뒤꿈치 Fz | 발 pitch | 발가락 높이 | **명령 CoP x** |
|---|---|---|---|---|---|
| +8 ~ 36 ms | ~120 N | ~100 N | +0.3° | 접지 | +2.5 → +4.9 cm |
| **+40 ~ 56 ms** | 211 N | **0 N** | +0.3° | 접지 | **+12.0 cm ← 발가락 한계에 고정** |
| **+60 ms** | 137 N | 80 N | | | **−5.0 cm ← 뒤꿈치 한계로 점프** |
| +72 ms | **0 N** | **446 N** | −1.8° | 3.4 mm | −5.0 cm |
| +120 ms | 0 N | 326 N | −6.1° | 15.2 mm | −4.4 cm |
| **+156 ms** | 4 N | 290 N | **−9.0°** | **24.8 mm** | −2.0 cm |
| +192 ms | 208 N | 276 N | +3.5° | **−11.4 mm** | +0.1 cm |
| +288 ms | 182 N | 132 N | +0.2° | 접지 | +4.3 cm (정상 롤오버) |

### 3. ★ 원인 — 명령 CoP 가 발의 한쪽 끝에서 반대쪽 끝으로 **순간이동**한다

**+56 → +60 ms, MPC 한 틱(10 ms) 사이에 CoP 명령이 +11 cm → −5 cm, 16 cm 를 점프한다.**
발가락 한계(`l_t` = 12 cm)에 꽂혀 있다가 뒤꿈치 한계(`l_h` = 5 cm)로.

그 시각이 정확히 **반대발이 떠나는 +56 ms** (이중지지 = 2·sf−1 = 14 %, 착지 후 몫 56 ms).
이중지지 동안 두 발이 나눠 지던 피치 모멘트를 **새 발 혼자 떠안으면서 QP 해가 뒤집힌다.**

CoP 가 뒤꿈치 **가장자리**에 꽂히면 발가락 하중은 **정확히 0 N**. 발목 토크가 발을
뒤꿈치 축으로 돌려 −9° 까지 들리고, CoP 명령이 중앙으로 돌아오는 +180 ms 에 내리찍힌다.

> **Q5 의 "합력 32 % → 142 % 스파이크"와 같은 순간이다** — +72 ms 의 뒤꿈치 446 N 이 그 142 %.
> **하중 인계 구멍(Q5) · 피치 CoP 포화(9/18 Q4) · 발 들림(Q8) 은 한 사건의 세 얼굴이다.**

### 4. 왜 뒤꿈치 끝까지 가야 하나

방금 착지한 발은 CoM 보다 **앞에** 있다. 수직력이 CoM 앞에서 작용하면 몸을 뒤로 젖히는
모멘트(`−r_x·Fz`)가 생기므로, MPC 는 CoP 를 최대한 CoM 쪽(= 뒤꿈치)으로 당겨 상쇄한다.
그런데 **G1 발은 뒤쪽 여유가 5 cm 뿐**이다 (앞은 12 cm). **필요한 쪽이 하필 짧은 쪽**이라 즉시 포화.

(참고: 착지 중립항 `T_st/2` 가 LIP 정확해보다 25 % 과대 — 발을 너무 앞에 놓는 것도
뒤꿈치 수요를 키운다. 다만 `lip_exact` 는 닫힌 루프에서 실패한 전례가 있다.)

### 5. 왜 점프를 아무도 안 막나 — **비용 함수에 막을 항이 없다**

- **`R = 1e-5`** 는 사실상 정규화가 없는 값 → QP 해가 제약 **꼭짓점에서 꼭짓점으로** 튀는 bang-bang
- **Δu 벌점이 없다** — 연속된 풀이 사이의 wrench 변화에 아무 비용이 없어 16 cm 점프가 공짜
- **CoP 제약이 발 크기 100 %** — 가장자리까지 허용하니 한쪽 하중 0 이 "합법"

### 6. 고칠 후보 (전부 MPC 층, 미검증)

| # | 처방 | 노리는 고리 |
|---|---|---|
| 1 | **CoP 안전 마진** — 제약을 발 크기의 ~80 % 로 축소 | 한쪽 하중 0 을 원천 차단. 가장 싸고 표준적 |
| 2 | **Δu 벌점** (연속 틱 간 wrench 변화) | 순간이동 자체 |
| 3 | **접촉 램프** — 떠나는 발 `Fz_max` ↓, 새 발 ↑ 를 서서히 | 인계 순간의 해 뒤집힘. reference 의 "착지 wrench 램프 0.02 s", **Q5 의 1순위와 같은 작업** |

> (Step 2). 모멘트만 비싸게 하는 건 답이 아니다 — 마진·램프·Δu 쪽이 맞다.

재측정: `.venv/Scripts/python.exe MPC/src/14_toe_lift.py --vx 0.5`

> 판정: **가능성이 높다. 다만 벽은 들림 자체보다 그 원인인 "피치 CoP 가 뒤꿈치 끝에 포화"이고,

> 계측: [15_toe_speed.py](../MPC/src/15_toe_speed.py) (속도별 120 s, 스텝 278개씩),

### 2. 0.6 이상에서는 발이 stance 의 절반을 뒤꿈치 선접촉으로 보낸다

|---|---|---|---|---|---|

| **+60 ms** | 182 N | 43 N | +3.4° | 접지 | **−5.0 cm ← 뒤꿈치 한계로 점프** |
| +80 ms | 0 N | **531 N** | −7.0° | 13.9 mm | −5.0 cm |
| +168 ms | 0 N | 300 N | **−26.2°** | **72.5 mm** | −2.0 cm |
| +228 ms | 83 N | 260 N | −12.1° | 33.3 mm | −1.9 cm |
| +288 ms | 76 N | 262 N | −3.9° | 9.7 mm | −2.3 cm |

- 0.5 와 달리 **발가락부터 착지**한다 (+8 ms 발가락 223 N, 뒤꿈치는 공중).
  이중지지 동안 MPC 가 새 발에 발가락 쪽 CoP(+8 ~ +12 cm)를 명령하기 때문.
- 반대발이 떠나는 순간 CoP 가 뒤꿈치 끝으로 튀고 (Q8 과 같은 사건), 발이 **−26°** 까지 뒤로 돈다.
- **+70 ms 부터 +290 ms 이후까지 발이 3° 이상 기울어 있다 = stance 의 절반 가까이.**

그 동안 발은 뒤꿈치 한 줄로만 땅에 닿는다. MPC 는 평발을 가정해 CoP 범위를
**−5 ~ +12 cm** 로 계획하는데, 실제로는 뒤꿈치 선보다 앞으로 CoP 를 옮길 수 없다.
**발목 피치 채널이 stance 절반 동안 사라지고, MPC 모델이 그만큼 틀린다.**

### 3. ★ 배포 RL 과 비교 — 같은 발, 순서가 반대다

같은 G1 발 (접촉구 4 개, 위치 동일), 같은 계측:

| | MPC 0.5 | MPC 0.6 | RL cmd 0.5 (실측 0.475) | RL cmd 1.0 (실측 0.915) |
|---|---|---|---|---|
| 첫 접촉 | 평발 (−0.3°) | **발가락 먼저** (+1.3° → +3°) | **뒤꿈치 100 %** (−4.3°) | **뒤꿈치 100 %** (−6.6°) |
| 착지 후 발가락 하중 0 | 111 ms | 179 ms | **0 ms** | **0 ms** |
| 발가락 들림 | 23 mm | 72 mm | **0 mm** | **0 mm** |
| 평발이 되기까지 | — | — | 약 20 ms | 약 20 ms |
| CoP 흐름 | +12 → −5 cm 점프 | 같음 | 뒤꿈치 → −1 ~ −2 cm 유지 → +12 cm 이륙 | 같음 |

RL 도 착지 직후 **CoP 를 뒤꿈치 끝(−5 cm)에 둔다**. 요구 자체는 MPC 와 같다.
차이는 **발이 이미 발끝을 든 상태(뒤꿈치 착지)에서 그렇게 한다**는 것.
그러면 뒤꿈치 CoP 가 발을 **앞으로** 굴려 평발로 내려놓는다 (자연스러운 방향).
MPC 는 평발/발가락으로 먼저 닿은 **뒤에** 뒤꿈치 CoP 를 요구하니, 발이 **뒤로** 돈다.

평발이 된 뒤 RL 의 CoP 는 −1 ~ −2 cm (뒤꿈치 예산의 20~40 %) 에 머물다가
+170 ms 부터 발가락으로 부드럽게 넘어간다. **착지 후 한 번도 포화하지 않는다.**
RL 의 뒤꿈치 하중 0 (70~100 ms) 은 stance **끝**의 발가락 이륙이다 (정상).
MPC 의 뒤꿈치 하중 0 (41~49 ms) 은 stance **처음**, 이중지지 중이다.

### 4. 반대 증거와 한계

- **0.5 에서 이미 23 mm 들리는데 추종은 103 %.** 들림이 있다고 곧바로 속도가 막히지는 않는다.
- **한 속도 안에서는 연결이 약하다.** 발가락 하중 0 구간이 짧은 1/3 과 긴 1/3 스텝의 반주기 평균 속도:

  | vx | 짧은 1/3 | 긴 1/3 |
  |---|---|---|
  | 0.5 | 96 ms → 0.514 | 120 ms → 0.515 |
  | 0.6 | 130 ms → 0.559 | 237 ms → **0.539** |
  | 0.7 | 90 ms → 0.470 | 278 ms → 0.468 |

  0.6 에서만 4 % 차이. 다만 속도는 여러 스텝에 걸쳐 보정되는 양이라 스텝 단위 비교는 약한 도구다.
- **속도 간 상관은 원인과 증상을 못 가른다.** Q7 의 "보폭↓ → CoP↓" 예측이 바로 속도 간
  상관에서 나왔다가 기각됐다. 확인은 개입 실험으로만 가능하다.

### 5. 판정과 다음 실험

들림은 **피치 CoP 가 뒤꿈치 끝에 포화하는 사건**의 얼굴이다. 포화율은 0 → 12 → 21 → 27 % 로
속도와 함께 자라고, 0.6 부터는 발이 stance 절반을 뒤꿈치 선접촉으로 보내 MPC 의 평발 모델이 틀린다.
→ **속도 벽의 원인 중 하나일 가능성이 높다. 미확정.**

인과 확인 = 들림만 없앴을 때 0.6 / 0.7 추종이 오르는가 (120 s):

1. **Q8 §6 후보** — CoP 마진, Δu 벌점, 접촉 램프. 한계에서 한계로 튀는 것을 먼저 잡는다.
2. **뒤꿈치 착지 (RL 에서 본 것)** — 스윙 끝에서 발끝을 4 ~ 7° 들어 닿게 한다.
   뒤꿈치 CoP 수요는 그대로 두고 **발이 도는 방향만 바로잡는** 쪽이라, 증상 억제가 아니다.
   단 지금은 이중지지 중 MPC 가 새 발에 발가락 CoP(+8 ~ +12 cm)를 명령하므로 그대로는 충돌한다.
   1번으로 튐을 먼저 잡은 뒤에 시도하는 게 순서다.

판정 지표: 0.6 / 0.7 추종 %, 발가락 들림 mm, 발가락 하중 0 ms, 몸 pitch.

### 2. 다른 것 — **착지점이 CoM 에 가깝다**

reference 착지 목표 (스윙 **시작 시 1 회 계산 후 고정**):

```
p_td = CoM(이륙 순간) + v_cmd · T_p,     T_p = (0.5 + k) · T_st
```

스윙 동안 CoM 이 `v·T_sw` 만큼 더 가므로, **착지 순간 CoM 대비 발 위치 = v · (T_p − T_sw)**.
9/15 분석에서 "착지목표 = CoM + v_cmd·T_st/2" 로 읽었는데, **기준 CoM 이 이륙 순간 값**이라는 점을 놓쳤다.

MIT 는 `k` 를 속도에 따라 **줄인다** (0.37 → 0.6 m/s 초과 0.28 → 0.65 초과 0.26).
설정값으로 계산한 착지 거리 (v = v_cmd 가정, 측정 아님):

|---|---|---|---|---|
| 0.3 | 3.5 cm | −3.0 cm (CoM 뒤) | 4.4 cm | 7.9 cm |
| 0.5 | 5.9 cm | −5.0 cm | 8.4 cm | **11.9 cm** |
| 0.6 | 7.0 cm | −6.0 cm | 9.3 cm | **12.8 cm** |

- **MIT 는 0.5~0.7 에서 착지 거리를 약 6 cm 로 묶어둔다.** 속도가 오르면 미리보기 계수를 손으로 줄였다.
  0.6 근처에서 무언가에 부딪혀 튜닝한 흔적으로 보인다 (이유는 코드에 적혀 있지 않다).
- **reference G1 은 발 중앙이 CoM 뒤에 닿는다.** 수요가 짧은 뒤꿈치 쪽이 아니라 긴 발가락 쪽에 걸린다.
  다만 CoP 범위가 `0.15 / 0.35` 로 실제 발(중앙 기준 ±8.5 / ±2.5~3 cm)보다 커서 MPC 가 진짜 발을 모른다.
- **reference 의 발 기준점은 발 중앙**(`foot_contact_site`, x = +3.5 cm), **우리는 발목**(x = 0).
  같은 착지 공식이라도 우리 발이 3.5 cm 더 앞에 놓인다.

**왜 이게 뒤꿈치 수요와 직결되나**: 발이 CoM 앞 `r_x` 에 있으면 수직력이 `−r_x·Fz` 의 뒤로 젖히는

**착지 거리를 줄이면 필요한 뒤꿈치 CoP 자체가 준다** — 억제가 아니라 필요를 줄이는 쪽.
